# SmartNF 가상 회원 5명 · MyPage 점검 안내

실제 사람과 무관한 개발용 자료다. 기간은 **2026-10-25~2026-11-01, 포함 8일**이다. 계정은 일반 회원(USER)이며 관리자 권한은 부여하지 않는다.

| 계정 | 화면 점검 상황 | 일일 기록 수 | 카드 순서 |
|---|---|---:|---|
| smartnf1@smartnf.com | 혈압·저염·걷기, 측정 환경/시간 차이 | 8 | 혈압 → 관리항목 → 건강정보 → 이력 → 보호 |
| smartnf2@smartnf.com | 체중·야식·걷기, 매일 작은 변동 | 8 | 체중 → 관리항목 → 이력 → 보호 |
| smartnf3@smartnf.com | 혈당 관련 식사 시간·단 음료 습관 | 8 | 관리항목 → 건강정보 → 이력 → 보호 |
| smartnf4@smartnf.com | 균형 잡힌 식생활·규칙적인 식사 | 8 | 건강정보 → 관리항목 → 체중 → 보호 |
| smartnf5@smartnf.com | 날짜·측정값 누락과 부분 실천 | 5 | 이력 → 관리항목 → 혈압 → 체중 → 보호 |

각 계정에는 건강정보 저장본 2개, 확정 관리항목, 개별 카드 구성을 넣는다. 혈당 관련 사용자의 혈당은 건강정보의 가상 참고값이며 일별 혈당 기록·그래프 기능을 새로 만든 것은 아니다. 건강정보 저장본의 `측정일`과 일일 기록 날짜는 과거 예시이고, 실제 DB 저장 시각·동의 이벤트 시각은 생성 명령 실행 시각이다. 과거에 실제로 동의/저장했다고 꾸미지 않는다.

실천 상태는 완료·일부 실천·미실천·미기록이 섞여 있다. `UNRECORDED`는 기존 서버 규칙에 따라 빈 실천 항목으로 생략되며 UI에서 미기록으로 표시된다. 5번 계정은 10/26·10/28·10/30에 기록이 없다. 미기록을 결식/실패로 해석하지 않는다. 수치 변화는 화면 점검용이며 식습관 개선 효과·진단·치료 목표를 뜻하지 않는다.

## 적용과 생성

1. 현재 서버를 `Ctrl+C`로 종료한다.
2. ZIP을 프로젝트 루트에 덮어쓴다. `run_local.sh`, `src/`, `docs/`가 같은 루트여야 한다.
3. 테스트를 실행한다.

```bash
bash ./gradlew test --no-daemon
```

4. 빌드 성공 후 한 번만 아래 명령을 실행한다. 기존 `.env.local`의 로컬 DB 접속 설정을 사용한다. MySQL root 로그인/수동 INSERT/새 마이그레이션은 필요 없다. 기존 V1~V8 테이블이 준비되어 있어야 하며 Flyway는 기존 실행기 설정을 따른다.

```bash
bash run_local.sh demo-seed
```

5. 요청했던 **공통 개발용 비밀번호를 두 번 입력**한다. 화면에 입력 글자가 나타나지 않는 것이 정상이다. 비밀번호는 명령행·코드·문서·ZIP에 기본값으로 넣지 않으며 기존 PasswordEncoder로 해시 저장한다. 이 안내에는 비밀번호를 재기록하지 않는다.
6. 콘솔의 `생성 5명 / 기존 가상 계정 유지 0명 / 삭제 0명`과 서버 실행을 확인한다. 이후 브라우저에서 `http://localhost:8080/login`으로 로그인한다. 다른 가상 계정으로 바꿀 때는 먼저 로그아웃한다.
7. `/mypage`에서 `Ctrl+F5` 후 대시보드·관리항목·실천/측정·변화/피드백을 비교한다. 기간을 2026-10-25~2026-11-01로 선택한다. 오늘 입력란이 비어 있는 것은 예시 기간 이후이므로 정상이다.

이 명령은 `local-demo` 프로필과 `127.0.0.1` 서버 주소를 명시한다. 애플리케이션 설정 URL과 실제 JDBC 메타데이터 URL 모두 로컬 MySQL의 `smartnf` DB인지 검사하며, 접속 호스트를 바꿀 수 있는 임의 JDBC 옵션은 거부한다. 원격 DB·다른 DB명·외부 바인딩·다른 활성 프로필 조합은 처리하지 않는다. 가상 자료는 로컬 점검용이며 운영/공개 배포 전 제거한다.

생성 완료 후 서버를 종료하고 아래 기존 명령으로 실행해도 자료는 유지된다. 일반 실행에는 자동 생성 동작이 없다.

```bash
bash run_local.sh
```

## 재실행·충돌·부분 실패

- `demo-seed` 재실행은 이미 표시된 가상 계정을 건너뛴다. 사용자가 편집한 기록·비밀번호·카드 순서를 덮어쓰지 않는다. 출력은 `생성 0명 / 기존 가상 계정 유지 5명`이다.
- 같은 이메일의 **표시되지 않은 기존 회원**이 있으면 전체 생성을 취소한다. 해당 계정이나 다른 기존 회원은 변경하지 않는다. 일부 실패 시 이번 생성 전체를 트랜잭션 롤백한다.
- 생성 직후 `[가상]` 표시 이름과 일일 메모로 구분한다. 식별은 이메일/이름만이 아니라 `LOCAL_DEMO_FIXTURE` 문서의 `FIXTURE_1~5` 연결로 한다. 이는 실제 사용자 동의가 아닌 내부 개발 자료 소유 표시이며 건강정보 동의 조회에 사용하지 않는다. 가입/건강 저장 동의 이벤트도 모두 합성 계정 전용이다.
- SNS 연결이나 USER 이외 권한이 추가된 가상 계정은 자동 생성/삭제 처리에서 중단한다. 새 권한·실제 개인정보를 가상 계정에 넣지 않는다.
- 공통 비밀번호를 바꾸려면 계정 설정에서 변경하거나, 아래 가상 계정 전체 삭제 후 다시 생성한다. 재생성은 편집한 가상 자료를 지운 뒤 초기 자료를 만드는 동작이다.

## 식사 기록의 현재 한계

- 식사 관련 내용은 **일일 실천 메모**다. 식사·영양 DB 저장은 아직 미연결이므로 실제 식사 달력에 음식·영양 수치가 채워지지는 않는다.
- 실제 달력은 기존처럼 저장 미연결을 표시한다. 체험 메뉴에서는 별도의 가상 식사 흐름을 볼 수 있지만 이 5명 계정의 DB 자료와 연결된 것이 아니다.
- 실제 식사 저장 연동은 후속 ERD·동의·권한·식품/분량·성분 출처·수정/삭제 정책 설계 후 진행한다.

## 가상 회원 5명 전체 삭제 (선택)

서버를 종료하고 명시적으로 다음 명령을 실행하면 **이번 생성기로 표시한 가상 회원과 그 회원의 기록·계정 설정을 삭제**한다. 현재 이메일/표시 이름이 바뀌었거나 이미 탈퇴한 가상 계정도 내부 표시로 찾는다. 가상 계정에 나중에 직접 입력한 기록도 삭제 대상이다. 되돌리기는 없고, 다시 생성하면 초기 예시를 새로 만든다.

```bash
bash run_local.sh demo-delete
```

일반 회원은 대상에 포함하지 않는다. SNS/추가 권한이 있거나 FK 의존성이 새로 생겨 안전하게 삭제할 수 없으면 전체 삭제를 취소하며 강제 FK 해제는 하지 않는다. 삭제 후 가상 자료 소유 표시 문서 1개는 남지만 회원/건강 기록 연결은 남지 않는다. 삭제된 회원 ID로 기존 세션을 계속 사용할 수 없으며 기존 세션 검사 흐름을 그대로 따른다.

## 검증 상태

- 완료: Bash 구문 검사, 모의 실행기로 일반/생성/삭제 명령 인자·루프백 바인딩·비밀번호 비출력·확인 불일치 중단 검사.
- 완료: Java 4개 파일 구문 검사, 실제 운영 검증 클래스로 10개 건강정보·5개 관리항목 목록·5개 카드 구성·37개 일일 입력 검증.
- 추가: Spring/H2 통합 테스트 5개 작성 — 해시/조회·재실행 보존·타인 보존·충돌/중간 실패 롤백·삭제 제한/탈퇴·로컬 실행 제한 검사. 이 환경에서는 Gradle 다운로드 DNS 제약으로 전체 실행하지 못했으므로 사용자 PC 결과가 필요하다.
- 미확인: 사용자 PC의 MySQL 생성·로그인·조회·편집·삭제, 실제 화면 피드백. 생성 성공 전에는 DB에 5명이 만들어졌다고 표시하지 않는다.

추가 로컬 검사: 실제 Runner에서 추출한 순수 guard 메서드로 로컬 연결 허용, 원격/다른 DB/호스트·소켓 옵션/공개 바인딩/혼합 프로필 차단을 확인했다. Spring 컨텍스트·실제 JDBC 접속 검사 실행과는 구분한다.
