# SmartNF 음식 탐색·참고 레시피 패치

2026-11-03 / 기존 육류 분류 개선(개선 문서 125절) 적용 프로젝트 기준.

## 적용

1. 실행 중인 서버를 종료한다.
2. ZIP의 `src/`, `docs/`, `scripts/`를 프로젝트 루트에 그대로 덮어쓴다. 외부 폴더를 추가로 만들지 않는다.
3. `bash run_local.sh`로 실행하고 브라우저에서 Ctrl+F5를 누른다.
4. `/preview/health/foods` → **음식·조리·가공**을 선택한다.

DB 마이그레이션, npm 설치, 가상 회원/식사 재생성은 필요 없다. 공개 영양자료와 회원·건강 DB는 변경하지 않았다.

## 확인 순서

- 음식 계열을 선택하고 큰 분류를 고른다. 식품 이름 입력란 클릭 → 하위 묶음 → 세부 분류 1(식품 종류) → 세부 분류 2(출처·세부 구분)로 좁힌다. 직접 이름을 검색해도 된다.
- **밥·죽·스프 → 죽 → 호박죽**을 선택한다. 결과 5건의 출처와 원본 영양값을 확인한다.
- 결과에서 ‘참고 레시피 있음’을 확인한다. 상세 ‘나의 선택에 담기’ → 음식명 옆 참고 레시피 버튼 → 버튼 아래 원문 확인 → 원하는 재료 체크 → **이 참고 레시피·선택 재료 연결**을 누른다.
- 아래 **나의 선택 식품 → 선택한 식재료**에서 음식명별 참고 재료 묶음과 개별 식재료가 구분되는지 확인한다. 같은 이름의 다른 음식 자료도 선택하면 각각 별도 묶음이다.
- 재료 하나/음식 하나의 레시피 연결을 해제하거나 부모 음식을 제외해도 다른 음식과 개별 식재료가 유지되는지 확인한다.
- 여러 참고 레시피가 있는 **가지볶음**에서 다른 후보 적용 시 확인/취소를 확인한다.
- 감자스프에는 현재 같은 이름의 보유 레시피가 없어 **레시피 미연결**로 나온다. 없는 레시피를 생성하지 않는다.

## 현재 적용 범위

- 계열 분류는 탐색 사전 기준이다. 국가·조리법 메타데이터가 없는 자료가 많아 **분류 미확인**을 유지했다. 계열 분류 전체 완료 상태가 아니다.
- 이름 일치 후보도 **참고 레시피**다. 음식 영양자료와 같은 조리법임을 입증하는 직접 연결 자료는 현재 없다.
- 체크한 재료는 원문 항목과 수량 그대로다. 실제 먹은 음식의 모든 재료를 뜻하지 않으며 **성분 자료 미연결**이다. 레시피의 영양값을 음식 영양값에 적용·합산하지 않는다.
- 참고 레시피·재료 묶음은 **이 화면에서만 유지**되고 새로고침·화면 이동 시 초기화된다. 계정/MyPage/식사 기록/가이드 전송은 미연결이다. ‘선택 식품 추가 확정’에도 참고 재료 묶음은 포함되지 않는다. 기존 음식·개별 식재료 선택/확정은 기존 정책을 따른다.
- 알레르기 has/review에서는 복합 레시피 선택을 보류한다. 조건 변경/부모 선택 만료·초기화 시 묶음을 정리한다.

변경 사항·보안 범위·검증·후속 개선은 `docs/SmartNF_IMPROVEMENTS.md` **126절**에 기록했다.

검증: `node --test src/test/js/*.cjs` 19개 통과. Chromium 실제 정적 템플릿/JS/CSS 1440/390px 음식·참고 재료·계열·영양값 불변·기존 식재료 회귀 검증 통과. 실제 Spring/MySQL 실행은 적용 후 확인이 필요하다. 서버 코드 변경이 없어 전체 Gradle 테스트는 반복하지 않았다.

`build_dish_search_details.py`는 원자료 갱신 시 출처 필터 파일을 재생성하는 개발용 스크립트이며 이번 적용에서는 실행할 필요가 없다.
