# 선택→관련 레시피→생활 장소 연결

- 건강정보: 이번 변경 없음.
- 영양정보: 기존 검색/직접 선택 유지, 공통 선택 식품으로 관련 레시피 최대6건 제공.
- 식품 선택 가이드: 기존 관리항목별 식품 예시와 직접 선택 유지, 일반 식생활 근거 범위를 표시하고 관련 레시피 제공.
- 관련 레시피는 원문 재료명의 명칭 경계를 확인하는 보수적 매칭. 배추를 양배추에 포함됐다는 이유만으로 매칭하지 않음. 순위는 명칭 일치 개수이며 영양/질환 추천 점수가 아니다. 추가 재료는 전체 재료 원문에서 확인, 코드 매칭 확정 없음. 국가별 문화권 자동 확정 없음.
- 레시피 선택 시 reference ID/시각만 같은 탭24시간 임시 보관. 식품 선택/건강 프로필/확정 목록을 덮어쓰지 않는다. 건강 식생활 조리 탭에서 원본 배합과 조리 단계 직접 표시.
- 알레르기 has/review이면 미검증 복합 레시피 소개/조리 안내 보류. 실제 안전한 추천 레시피 DB를 확보하면 검토 기반으로 확장.
- 건강 식생활: 반복 선택편집/확정 목록/일반 안내 카드/레시피 전체검색/성분비교 도구를 제거하고 상단 요약+3탭으로 정리. 선택편집은 식품 선택 가이드로 연결. 기존 실험 도구 소스는 보존하지만 이 페이지에서 로드하지 않는다.
- 장보기와 외식: 네이버 지역/업종 검색. 지도 설정은 NAVER_MAP_SETUP.md. 실제 주변 전체 매장/거리/재고/메뉴 영양 연동은 아님.
- 아직 없는 범위: 실제 매장 원재료/양념, 검증된 질환별 추천 기준 전체, 건강 적합 레시피 판정, 인분/영양 최적화. 자료 없는 항목은 만들어내지 않는다.
- 기존 레시피1156 중 재료 있는1153건 사용. API 신규 수집/공식 자료 전체 확보를 완료한 것으로 표현하지 않는다. 기존 지방/혈압 등 추천 예시는 일반 기준이며 의료식 처방 아님.
- AI레시피·식단: 생성·정량 최적화·월간 일정 후속. MyPage: 확정/삭제/실제 섭취·기간 평가 후속. 이번 해당 페이지 변경 없음.

## 적용·확인
ZIP 프로젝트 루트 덮어쓰기 → ./gradlew classes → 서버 재시작 → Ctrl+F5. 기존 영양DB 유지.
2·3페이지에서 부추 등 식품 선택 → 하단 기존 레시피 소개 → 조리 방법 보기 → 4페이지 조리 탭. 장보기/외식에 지역 입력. 키가 없으면 미설정 안내와 네이버 지도 검색 링크가 표시되는 것이 정상.
