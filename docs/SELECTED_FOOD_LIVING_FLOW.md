# 선택 음식 → 건강 식생활 관리 가이드 연결 (2026-10-26)

## 확인 순서
1. ZIP을 기존 smartnf 프로젝트 루트에 병합합니다.
2. 서버 재시작 후 브라우저 Ctrl+F5를 누릅니다.
3. http://localhost:8080/preview/health/recommendations 에서 ‘추천 재료 활용’ 음식 한두 개를 담습니다. 예: 순두부 사과 소스 오이무침, 고등어구이. 실제 표시 여부는 관리조건/알레르기에 따라 다릅니다.
4. 아래 ‘선택한 식품으로 식생활 가이드 보기’ 또는 http://localhost:8080/preview/health/diet 로 이동합니다.
5. 상단의 **안내를 볼 선택 식품**에서 하나를 고르면 장보기·조리하기·외식하기가 같은 식품을 기준으로 바뀝니다.

## 장보기
- 선택한 레시피 원문의 재료·양념·중량을 준비 체크 목록으로 표시합니다.
- 괄호 안의 쉼표(예: 빨간색, 노란색)와 숫자의 쉼표(1,000g)는 유지합니다. 줄바꿈·원문의 쉼표/구분 제목을 기준으로 보기 좋게 나눈 목록입니다.
- 소스/양념 등의 구분 제목은 체크 항목과 구분합니다. 원문 한 구간에 여러 재료가 남을 수 있으므로 재료 코드별 완전 분해나 중량 합산이 아닙니다.
- 체크는 같은 화면에서 식품을 오가면 임시 유지하며 새로고침하면 초기화됩니다. 계정 저장·실제 구매 기록 아님.
- 아래의 기존 지역 시장·마트·구매처 찾기를 유지합니다. 해당 매장에 재료가 있다는 재고 확인 결과는 아닙니다.

## 조리하기
- 선택한 **레시피 ID**로 원본을 정확히 찾고 이름·재료 원문 일치를 확인합니다. 비슷한 음식명의 첫 레시피를 대신 쓰지 않습니다.
- 재료·양념 원문, 만드는 방법, 원문 인분 중량 표기를 제공합니다.
- 원문에서 확인되는 소금·간장·설탕·소스·기름/오일·유제품 등 확인 대상을 따로 보여줍니다. 표시 구간 자체를 저염/저당/적합성 판정으로 사용하지 않습니다.
- 기존 선택 관리항목에 연결된 조리 활용 안내와 출처는 그대로 유지합니다.
- 원문이 없는 인분·중량을 추정하거나 적정 섭취량/영양 합계/예상 건강 효과를 계산하지 않습니다.

## 외식하기
- 선택 음식명을 보여주고 실제 매장의 원재료·양념·소스·고명·분량·조리법 확인 질문을 제공합니다.
- 레시피에 적힌 소스·양념과 재료 목록을 비교 참고로 볼 수 있습니다. 원문 레시피는 매장의 실제 레시피가 아닙니다.
- **네이버 지도에서 이 음식 검색** 링크가 현재 선택 음식명과 아래 지역 입력값을 검색어로 사용합니다. 지역을 비우면 음식명 검색입니다.
- 기존 지역·업종의 장소 검색과 지도 표시 코드는 유지했습니다. 내부 목록/지도는 기존 네이버 인증정보가 있어야 작동하며, 인증정보가 없으면 외부 네이버 지도 검색 링크로 안내합니다.
- 이번에 실제 네이버 인증키·SDK 운영 연결을 새로 검증한 것은 아닙니다. 시험에서는 키 미설정 상황의 안내와 외부 검색어 연결을 확인했습니다.

## 상태 연동
- 현재 임시 선택 목록만 사용합니다. 해제한 음식을 확정 목록에서 다시 가져와 표시하지 않습니다.
- 여러 선택 중 안내할 하나를 고르며, 해당 선택이 제거되면 남아 있는 식품으로 전환하거나 빈 상태를 표시합니다.
- 알레르기 검사에서 제외되거나 구성 검증이 되지 않은 음식은 안내에서 제외합니다. 미입력은 기존 안내와 함께 진행합니다.
- 예전 `smartnf.recipe-reference.v1`에 남아 있는 별도 레시피 선택값을 사용하지 않습니다. 현재 선택과 관계없는 이전 조리법이 나타나는 문제를 방지합니다.
- 원문 자료를 불러오지 못하면 재시도 버튼을 제공합니다.

## 원문 레시피가 없는 경우
일반 음식 DB의 현미밥이나 직접 선택한 식재료처럼 원문 조리법이 연결되지 않은 항목은 **원문 미연결**로 표시합니다. 음식 DB의 영양 성분을 근거로 전체 재료·배합·조리법을 추정하지 않습니다. 음식명으로 네이버 지도 검색은 제공할 수 있지만 실제 메뉴 제공 여부·적합성은 확인하지 않습니다.

이번 연결은 원문 레시피가 있는 추천 재료 활용 음식 105개가 중심입니다. 기존 일반 음식 DB 5개와 모든 식재료에 동일한 원문 조리법이 확보된 것은 아닙니다.

## 파일
- `src/main/resources/static/js/selected-living-data.js`: 원문 구간 표시, 원본 ID 대조, 양념 구간 추출, 지도 검색어
- `src/main/resources/static/js/health-living.js`: 선택 식품 공통 전환과 세 탭 연결
- `src/main/resources/templates/preview/health/diet.html`: 새 스크립트와 캐시 버전
- `src/main/resources/static/css/food-choice.css`: 장보기 체크 목록/식품 선택 입력 반응형 스타일
- `python/food_recommendation/test_selected_living_data.cjs`: 원본·분리·검색어 검증

생성형 AI나 새로운 API 수집 없이 보유 레시피를 사용했습니다. 기존 추천/선택/확정 계약은 유지하며 다른 페이지 레이아웃·DB를 수정하지 않았습니다.

## 후속 작업
- **MyPage**: 장보기 체크/실제 구매/실제 조리·섭취 기록을 계정에 저장하려면 별도 기록 모델과 삭제·수정·기간 관리를 연결합니다. 이번 체크는 저장 기록 아님.
- **AI레시피식단**: 인분/실제 섭취량/재료 코드·배합 검증 후 영양 계산과 월간 식단에 적용합니다. 현재 안내를 최적 식단으로 취급하지 않습니다.
- **Backend**: 원본 레시피 ID·버전·선택 당시 조건과 기록 이력을 구분합니다. 장소 API의 매장 목록과 영양자료를 임의로 같은 매장 메뉴로 합치지 않습니다.
- **Python**: 원문 구간을 실제 재료 엔티티로 확정하려면 명칭·양념/소스 배합·단위·인분·제품 표시를 추가 검토합니다. 재료 수량 합산은 그 이후 수행합니다.

## 검증
105개 보유 레시피의 ID/이름/재료 원문 대조, 괄호·숫자 쉼표 유지, 원문 불일치 거부, 페이지 이동 후 선택 유지, 체크/해제, 식품 전환과 원문 조리법, 지역+음식 지도 링크, 키 미설정 안내, 선택 해제/알레르기 적용 후 이전 음식 제거, 원문 없는 음식 미추정,320/390/1440px 가로 넘침·JS 오류 확인 통과. 기존 추천 검증도 통과. Java 서버 빌드·계정 DB 저장·실제 네이버 API 운영 호출은 수행하지 않았습니다.
