# 선택 음식 중심 장보기·조리·외식 (2026-11-05)

## 변경
- 별도의 선택 식품·계획 관리 카드를 화면에서 제거. 기존 원본 MyPage 관리 경로/DB 유지.
- 선택한 목록 카드 아래 음식별 체크박스 제공. 카드 첫 선택 시 포함 음식 전체 선택, 음식 개별 해제/재선택 가능. 카드 재선택/세 단계 전환시 음식 선택 유지. 다른 목록에 동일 식품이 있어도 원래 목록별로 구분.
- 장보기/조리하기/외식하기는 체크한 음식만 표시. 미선택 음식/연결재료/조리법은 표시하지 않는다. 조리하기에는 날짜/계획 저장 버튼 없음. 저장된 참고 레시피만 기존 알레르기/버전 검증 후 펼침 제공.
- 선택한 목록 제목 옆에 장보기 날짜 또는 외식 날짜와 계획 저장 배치. 날짜 입력만으로 저장하지 않고 확인 후 기존 /plans/move API 사용. 선택 음식만 원래 목록에서 이동하며 미선택 음식과 타목록/목적 날짜 기존 계획은 보존. 일반/건강관리·질환 분류/연결 레시피·재료 유지.
- 여러 목록은 원래 인덱스 역순으로 목록별 이동. 각 이동은 기존 서버 원자적 처리이며 여러 목록 전체가 하나의 트랜잭션인 것은 아니다. 중단 시 완료 개수 안내. 최신 revision/원본 스냅샷/저장 동의/알레르기를 확인해 다른 변경을 덮어쓰지 않는다.
- 응답 불확실 시 동일 requestId/본문 재시도, 완료한 목록을 다시 이동하지 않는다. 저장 진행/불확실 중 날짜·카드·음식·단계 변경 잠금 및 이탈 경고. 결과 재조회 경로 제공. 오류시 이미 완료된 목록은 유지한다.
- 기존 재료 제외는 해당 목록에만 반영. 음식 선택에서 숨긴 재료는 제외 대상에서 제거해 숨은 항목을 삭제하지 않는다. 새 API/DB schema/건강 필드 추가 없음.

## 검증
- JS3개 문법, Node 데이터4개 통과.
- 실제 guide/editor/stage-save Chromium+대역 API에서 음식별 필터/단계 선택 유지, 관리 카드 없음, 조리 날짜·저장 없음, 장보기·외식 날짜 표시 확인.
- 두 관리 구분 목록의 선택 음식만 이동/미선택 원본과 목적 날짜 목록 보존/재료 유지, 응답 유실 후 동일 요청 재시도/중복 없음, 저장 중 잠금,5개폭/JS오류 없음 확인.
- 다중 카드·개별 제외·매장 검색 회귀도 통과. 실제 사용자 MySQL/네이버 검증으로 확대하지 않는다. 브라우저 테스트3종 포함.

## 적용
154절 환경 서버 종료→ZIP src/docs 폴더 병합→bash run_local.sh→Ctrl+F5. DB 초기화/마이그레이션 불필요.
날짜 조회→카드 선택→음식 체크 조정→세 화면에서 선택 음식만 표시 확인. 장보기·외식 날짜 입력→계획 저장→MyPage 목적 날짜/원래 목록 잔여 음식 확인.
