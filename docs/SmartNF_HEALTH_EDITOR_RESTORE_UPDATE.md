# 로그인 건강정보 자동 불러오기·수정

2026-11-04. 직전 오늘의 선택 업데이트(개선 기록 141절) 적용 환경에 병합합니다.

## 적용
서버 종료 → ZIP의 src/docs를 프로젝트의 같은 위치에 병합 → `bash run_local.sh` → Ctrl+F5.
Java 경로 처리가 바뀌므로 서버 재시작이 필요합니다. DB migration/npm 빌드는 없습니다.

## 확인
1. 로그인 후 헬스케어의 건강정보 메뉴를 엽니다. 기존 `/preview/health/info`에서도 계정용 화면이 표시됩니다. 비로그인은 기존 체험 화면을 이용합니다.
2. MyPage 최신 저장 수치·질환·진단 시기가 입력란에 복원되고 마지막 저장일(한국 시간)이 보이는지 확인합니다. 계정 저장본이 없으면 빈 입력 상태입니다. 저장 동의가 없으면 동의 안내를 먼저 확인합니다.
3. 입력란을 수정하고 상단 확인 체크를 선택한 뒤 상단 또는 폼 아래 ‘변경사항 저장’을 누릅니다. 화면 조회만으로 서버에 자동 저장하지 않습니다.
4. MyPage에서 새 저장본을 확인하고 다시 건강정보 메뉴에 들어가 수정값이 복원되는지 확인합니다. 수정값을 저장하기 전 페이지를 떠나면 브라우저의 기본 이탈 확인이 표시됩니다.
5. 건강정보 수정 후 관리항목은 재검토·확정을 안내합니다. 알레르기 조건을 건강정보 저장에 추가하거나 기존 계획의 관리 코드를 변경하지 않습니다.

## 검증
실제 HTML과 bootstrap/profile/account JS를 DOM 환경에서 실행해 수치·체크박스·월 입력 복원, 저장 시각, 자동 POST 없음, 미저장 이탈 방지, 확인 체크·하단 저장, expected profile/consent 전달, 실패 시 입력 보존·같은 요청 ID 재시도, 저장 후 경고 해제, 저장본 없음/동의 없음 차단을 확인했습니다. 기존 bootstrap/API Node 회귀 2개 및 JS 문법도 통과했습니다.

새 HealthEditorPageTests에 로그인/비로그인·본인 계정 분리·개인 화면 no-store·복원 메타데이터 검증을 추가했습니다. Java 21 전체 Gradle/Spring 및 실제 MySQL·로그인 검증은 이 환경에서 실행하지 못했으므로 사용자 환경에서 `./gradlew.bat test`와 위 순서로 확인하세요. DOM/API 대역 검증을 실제 서버 저장 성공으로 간주하지 않습니다.
