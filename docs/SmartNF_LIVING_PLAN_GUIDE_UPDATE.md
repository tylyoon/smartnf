# 건강 식생활 관리 가이드 업데이트 (2026-11-04)

## 적용
직전 그래프 정렬 업데이트(개선 기록 138절)가 적용된 프로젝트에 ZIP의 src/docs를 같은 위치로 병합합니다. 서버를 종료한 뒤 `bash run_local.sh`로 실행하고 브라우저에서 Ctrl+F5를 누르세요. DB migration, npm 설치, 새 환경변수는 없습니다.

## 화면 확인
1. 건강 식생활 관리 가이드에서 **MyPage 저장 계획**을 선택하고 날짜를 조회합니다.
2. 일반 계획/건강관리 및 장보기/외식으로 좁힌 뒤 계획을 선택합니다. 건강관리 항목은 계획의 분류이며 로그인한 본인 건강정보로 덮어쓰지 않습니다.
3. 장보기에는 저장한 식품과 직접 연결한 참고 재료만 표시됩니다. 준비 체크는 임시 표시입니다.
4. 조리하기에서 저장 당시 레시피 버전과 선택 재료 원문이 일치하면 조리 순서를 표시합니다. 레시피 미연결/자료 변경 시 임의 조리법을 만들지 않습니다. 제외한 재료가 원문 조리법에 남을 수 있으므로 전체 원문도 확인하세요.
5. 외식하기에서 식당명과 방문 시간을 저장하고 MyPage에서 유지되는지 확인하세요. 장보기·건강관리 분류와 재료는 보존합니다. 미저장 방문 정보가 있으면 날짜 연동이 입력을 지우지 않습니다.
6. 현재 임시 선택으로 전환하면 기존 선택 식품의 장보기·조리·외식 안내를 이용할 수 있습니다. 저장 계획과 별개입니다.
7. 매장/외식 장소 찾기는 펼쳤을 때 기존 검색 기능으로 연결됩니다. 실제 장소 제공자 키·설정은 기존 환경을 사용합니다.

## 검증과 범위
- Node 24개 통과. 실제 템플릿·JS·JSON과 가상 계정 API를 사용한 Chromium 검증: 날짜/일반·건강관리 구분, 저장 재료 체크, 버전 확인 조리법, 외식 저장 시 다른 계획/관리 코드/재료 보존, 텍스트 안전 표시, 임시 선택 불변, 320/390/800/1440px, 권한 거절·동의 철회 시 내용 제거, 비로그인 개인 API 미요청, JS 오류 없음.
- 사용자께서 기존 저장 계획의 재로그인 유지를 확인했습니다. 이번 새 가이드의 실제 Spring/MySQL 통합 동작은 사용자 서버에서 위 순서로 확인해야 합니다. 전체 Gradle 서버 테스트 완료로 간주하지 않습니다.
- 개인 식단 처방, 일일 섭취 합계, 질환 적합성 판정, 새 레시피 추정은 이번 범위에 포함하지 않습니다.
