# 195절 맛 슬라이더와 카드 구성

## 변경 범위

recipe-taste.js, recipe-taste.css, health/my-recipes.html 세 파일만 변경한다. 기존 194절의 계정·CSRF·revision·AI 캐시·실제 평가 분리 및 서버 저장 구조를 유지한다. 신규 Java/DB 마이그레이션은 없다.

맛 강도 선택 상자와 별도 막대를 native input[type=range] 하나로 통합한다. 최소0·최대5·간격1. 출력 숫자는 드래그/클릭/키보드 조작에 맞춰 변경한다. native range 자체에는 null이 없으므로 별도 known 상태를 사용한다. 미확인일 때 포인트를 숨기고 ‘미확인’이라고 표시하며 저장 시 해당 키를 생략한다. 0점은 명시적으로 저장한다. 왼쪽 끝 클릭으로도 미확인에서 0점을 선택할 수 있다. × 또는 Delete/Backspace로 미확인으로 되돌린다.

별 크기는 20px로 낮추고 두 평가를 각각 라벨+별 한 줄로 만든다. 미평가/점수/해제 문구는 화면에서 제거한다. 빈 별과 채운 별로 구분한다. 선택한 별을 다시 클릭하면 null로 돌아간다. 스크린리더에는 미평가/현재 점수를 설명하고 기존 라디오 그룹·키보드 조작을 유지한다. 모바일에서는 모양보다 클릭 영역을 크게 둔다.

상단 사진·음식명·분류·별점의 간격을 줄인다. 하단은 재료·분량, 조리 순서, AI 분류·예상 맛 순서의 3열로 배치한다. 1100px 이하에서는 AI 영역을 두 열 아래로, 650px 이하에서는 전체를 한 열로 배치한다. 별점은 760px 이하에서 음식명 아래에 놓는다. 숫자/식감/향·먹어본 뒤 수정 체크·저장 버튼은 AI 영역에 함께 둔다.

## 검증

실제 프런트엔드 JS를 JSDOM+모의 API로 실행해 6개 슬라이더/분류 선택 2개, 실시간 숫자, 미확인과0 구분, 지우기, 0점 저장 시 AI 원본 보존, 작은 별점 토글, 구 평가 변환, 별점 키보드 이동, 늦은 AI 응답의 편집 내용 보존을 확인했다. 실제 템플릿의 재료/조리/AI 세 열 순서와 JS 문법도 확인했다.

JSDOM은 레이아웃을 그리는 브라우저가 아니다. 실제 포인터 드래그·모바일 터치·시각 배치와 사용자 DB에서 재방문 복원은 별도 사용자 확인이 필요하다. 서버 로직은 바뀌지 않아 Java/DB 회귀 검사를 반복하지 않았다.
