# 건강정보 확정 → MyPage 계정 저장 연결 수정

2026-11-04 / 144절 업데이트 적용 환경 기준

## 원인
- 사용자가 방문한 /preview/health/info의 확정 버튼은 sessionStorage에 최대 24시간 임시 보관했다. 계정 프로필 API를 호출하지 않았다.
- MyPage의 나의 건강정보는 계정 DB를 조회하므로 임시 확정만 한 경우 빈 상태가 맞다. 직전 ‘확정하면 계정 저장’ 안내는 이 경로에 대해 잘못됐다.

## 변경
- 로그인한 /preview/health/info는 현재 /health/info의 계정용 입력 화면과 서버 스냅샷을 사용한다. 비로그인은 공개 임시 입력으로 유지한다. 로그인 여부만으로 저장 요청하지 않는다.
- 계정용 화면은 폼 아래 ‘나의 건강정보 확정’ 영역에서 입력 확인 체크 후 ‘건강정보 확정 · MyPage에 저장’으로 한 번 저장한다. 기존 브라우저 임시 확정 버튼은 계정 모드에서 만들지 않는다.
- 실제 서버 저장 성공 시 저장 시각·ID와 MyPage 링크를 표시한다. 입력 내용이 같으면 새 버전을 만들지 않는다. 목표 날짜/체중 방향과 기존 폼 검증을 유지한다.
- 요청 중에는 입력을 잠근다. 응답이 불확실하면 동일 UUID/본문으로 재시도하며 완료 전 성공 표시하지 않는다. 409 및 계정/동의 거절은 새로고침하여 재확인하도록 차단한다.
- DB 저장본이 없고 이 탭에 이전 임시 확정본이 남아 있으면 ‘이 탭의 이전 임시 확정본 불러오기’를 표시한다. 본인 입력인지 명시적으로 확인한 뒤 복원한다. 불러오기만으로 서버에 전송하지 않으며 다시 확인 체크/확정해야 계정 저장된다. 만료·잘못된 형식은 거부한다. 이전 탭을 닫았거나 24시간이 지났거나 저장소가 지워졌다면 복원을 보장할 수 없다.
- 현재 MyPage 셸과 메뉴, 음식 선택·장보기·외식 계획은 변경하지 않는다. /mypage 경로를 과거 페이지로 바꾸지 않는다. 알레르기는 기존 별도 조건이며 이번 프로필 저장 범위에 추가하지 않는다.

## 적용
1. 가능하면 기존 입력 탭을 유지한다.
2. 서버 종료 후 ZIP 내용을 프로젝트 루트에 폴더 구조 그대로 덮어쓴다.
3. bash run_local.sh 로 서버를 시작한다.
4. 기존 탭에서 Ctrl+F5 후 로그인한 건강정보 화면을 연다.
5. 필요한 경우 이전 임시 확정본 불러오기 → 본인 입력 확인 → 확인 체크 → 건강정보 확정 · MyPage에 저장.
6. ‘MyPage에 저장 완료’ 표시 후 MyPage → 나의 건강정보에서 확인한다.

새 DB 마이그레이션·DB 초기화·npm 빌드는 없다. 기존 계정 저장 동의가 없으면 MyPage의 동의 화면에서 처리한 뒤 입력 화면을 다시 연다.

## 검증
- Java21/Gradle9.8.1 관련 서버 36개: CurrentMyPageHealthTests 2, HealthStorageTests 22, FoodPlanTests 12 통과. 현재 MyPage 4개 경로의 셸 유지, 로그인 건강정보 계정 모드 및 비로그인 공개 모드/no-store 회귀 포함.
- 기존 Node JS 테스트 41개 통과, 변경 JS 문법 검사 통과.
- 실제 Spring Boot/Security/Thymeleaf와 별도 H2 테스트 계정 브라우저: 공개 화면 → 로그인/동의 → 동일 메뉴 계정 모드 → 이전 임시 입력 명시 복원(자동 POST 없음) → 확인 체크 → 단일 확정 API 저장 → MyPage 동일값 → 수정/서버 저장 후 응답 유실 모의/동일 UUID 재시도 → 새 로그인 복원, JS 오류 없음 확인.
- 실제 사용자 MySQL에는 접근하지 않았다. 사용자의 과거 임시 입력/DB 저장본 유무는 적용 후 본인 계정에서 확인해야 한다. 전체 Gradle 테스트/운영 검증 성공과 구분한다.
