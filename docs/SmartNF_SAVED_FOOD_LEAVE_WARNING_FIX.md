# 저장 후 페이지 이동 경고 수정 (2026-11-05)

## 원인과 변경
저장 상태 비교에 현재 조회 중인 관리 카드 조건이 포함되어, 혈압에서 식품을 MyPage에 저장한 뒤 신장질환/기타 카드로 이동하면 식품 변경이 없어도 미저장으로 인식했다.
조회 카드와 저장한 식품·레시피·재료의 변경 비교를 분리했다. 카드 조회만으로 저장 상태나 저장 당시 관리 구분을 변경하지 않는다. 저장 완료한 동일 식품·재료는 이동 경고를 표시하지 않는다. 실제 식품/레시피/재료 변경 및 저장 요청 진행·결과 불확실 상태의 이탈 보호는 유지한다. 저장본 이후 모든 식품을 제외한 경우도 변경으로 인식한다.
계정 API/서버/DB 구조·저장 데이터 변경 없음. 두 식품 페이지의 JS 캐시 버전 갱신.

## 검증
Node 관련27개 통과. 실제 food-plan-save.js를 실행한 Chromium에서 대역 계정 API로 저장→신장 카드 조회→두 이동 링크 확인 시 경고 없음, 재료 변경 시 경고 유지 및 JS 오류 없음 확인. 실제 사용자 계정/MySQL 저장 재검증으로 확대하지 않는다.

## 적용
서버 종료 → 프로젝트 루트에 ZIP src/docs 병합 → bash run_local.sh → Ctrl+F5.
확인: 식품을 오늘의 선택에 저장 → 신장질환 클릭 → 두 안내 링크로 이동. 변경하지 않았다면 경고 없음. 저장 후 식품·재료를 수정한 경우에는 경고 유지.
