# SmartNF 고혈압 본문 검토 및 화면 연결 준비

- 검토일: 2026-10-22
- 입력: 사용자가 제공한 data.zip의 실제 API 원본·구조화 JSON 및 분류 결과.
- 범위: 원본 무결성 확인, 고혈압·식이·운동 3건 본문 읽기, 공식 페이지 교차 확인, 기존 관리항목 6개에 근거 위치 연결.
- 원본·화면·DB는 변경하지 않는다. 임상 규칙 승인과 원문 서비스 재게시 허용을 의미하지 않는다.

## 1. 파일 확인 결과

658쌍의 JSON·XML을 읽어 XML 해시·응답 ID·제목·소제목 내용을 대조했다. 불일치는 0건이었다. 이전 메타데이터 검토와 달리 이번에는 실제 XML을 대조했다. 원문 내용의 의료적 정확성을 658건 모두 검증했다는 뜻은 아니다.

정제 후 전체 658건 재분류를 실행했다. 원본 확인 필요 0건, 주제 미분류 0건, 제목 분류 검토 반영 16건, 원본 변경으로 미반영 0건이었다. 승인 관찰 목록 미확인 5283/6808/6809는 유지한다.

## 4. 자동 수치 적용 전에 확인할 부분

### 서로 다른 소금 기준

6765의 생활관리 설명에는 하루 소금 6 g, 6855의 식이 설명에는 하루 소금 5 g이 나온다. 어느 페이지가 더 최근이라는 이유만으로 하나를 개인 목표로 채택하지 않는다. 기준 목적·적용 대상·원 지침 버전을 구분하고 소금 g과 나트륨 mg을 같은 단위처럼 비교하지 않는다.

대한고혈압학회 공식 자료실에 2026 제6판 수정본이 등록된 것은 확인했다. 해당 PDF 전체의 수치·적용 조건까지 검토 완료한 상태는 아니므로, 혈압 판정·치료 목표·섭취 목표의 자동 규칙은 보류한다.

### 식생활의 개인 제한

6855에는 콩팥질환과 칼륨 관련 주의가 포함된다. 건강한 식품군이라는 이유로 모든 사용자에게 같은 양을 권하거나 칼륨 보충을 일괄 추천하는 구조로 연결하지 않는다. 개인 식이 지시와 제한 정보를 먼저 확인한다.

### 운동·수분·증상 조건

5303에는 현재 상태·질환·운동 중 증상·저항 운동 관련 주의가 함께 있다. 운동 시간만 따로 떼어 일괄 적용하지 않는다. 일반적 실천 방법의 회당 시간·횟수와 주당 합계 표현은 대조가 필요하다. 수분량·심박수·강도도 개인 상태 확인 없이 공통 목표로 자동 생성하지 않는다.

### 측정·비교와 목표의 분리

가정/진료실 등 측정 환경, 반복 측정값과 측정 시각을 구분할 입력이 필요하다. 단일 측정값을 진단으로 확정하거나 분류 경계를 치료 목표로 사용하지 않는다. 연령·성별 또래 분포는 이 3개 자료만으로 계산하지 않으며 적합한 통계가 별도로 필요하다.

## 5. 번역 위젯 정제

실제 5303 API 본문에 번역 위젯의 표시 문구와 HTML script 태그 밖에 나온 자바스크립트 조각이 섞여 있었다. 공식 페이지에서도 해당 위젯 문구가 확인되어 우리 수집기가 생성한 글로 보지는 않는다.

- 정제 대상은 5303 한 자료의 63개 항목이다. 63개 항목 전체를 삭제했다는 뜻은 아니다.
- 식별된 번역 위젯 전용 조각은 분류 대상에서 제외한다. 건강 본문에 붙은 번역 표시 문구는 표시 문구만 제거한다.
- 원본 XML/JSON은 유지한다. 소제목의 기존 인덱스를 보존하고 `text_cleanup`에 정제 이유를 기록한다.
- 임의의 영문 문장이나 한국어가 섞인 미확인 본문을 통째로 지우는 일반 규칙은 사용하지 않는다.
- 주제·용도 건수는 정제 전후 동일했다. 건강 지식 650, 식생활 479, 운동 359, 응급대처 1, 주의 검토 533이다. 이는 언급 기반 후보 수이며 검증된 지침 개수가 아니다.

수정 코드를 프로젝트에서 실행하면 새 classified 실행 폴더에 정제 기록이 저장된다.

```bash
python python/health_collection/health_classify.py --expected-count 658
```

기대: 658건 처리, 원본 확인 필요 0, 제목 검토 반영 16, 번역 위젯 정제 1개 자료/63개 항목. API 호출·TOKEN 읽기 없음.

## 7. 이용조건 확인 상태

3개 공식 웹페이지에는 공공누리의 출처표시·상업적 이용금지·변경금지 조건이 표시되어 있다. 사용자의 API 신청 승인 사실과 웹페이지의 재게시·변형 조건을 별도로 확인해야 한다. API 승인만으로 요약·변형·LLM 입력·재배포 범위까지 확정됐다고 판단하지 않는다. 이번 전달 ZIP에는 원문 658건이나 이미지·개인 TOKEN을 넣지 않고 코드·자체 검토 메모·근거 위치만 포함한다.

## 8. 검증과 출처

Python 테스트 31개와 승인 목록 추출기의 Node 오프라인 검사 통과. 받은 실제 658건으로 재분류 실행도 통과했다. 별도 검증 작업 폴더를 사용했으며 사용자 원본 ZIP과 프로젝트 파일은 직접 변경하지 않았다. `bp_archive_audit.json`에 무결성 확인 수·정제 범위 등을 기록했다.
