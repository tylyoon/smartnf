# SmartNF 258: 장보기 조사 예산과 실제 판매상품 비교 분리

## 사용자 확정 기준
- KAMIS·참가격은 장보기의 필요량 예상금액·총예상금액에 사용합니다.
- 가격 비교 화면은 실제 판매상품·포장량·단가·구매 개수·배송비 비교 및 명시적인 상품 선택에 사용합니다.
- 256~257 및 과거 문서의 '조사자료 없을 때 정기 판매상품 가격으로 예산 보완' 정책은 이번 사용자 지시에 따라 폐지합니다. 조사가격이 없으면 예상금액은 미확인이고, 실제 선택 상품 구매금액은 별도입니다.

## 변경 내용
1. `price-budget.js`: 예산 자료는 KAMIS/CHAMPRICE만 허용합니다. market 판매상품으로 예상금액을 채우는 fallback을 제거합니다.
2. `shopping-budget.js`: 장보기/MyPage의 조사 기준 합계와 선택 상품 구매금액을 별도로 표시합니다. 조사자료 미확인은 합계 제외·부분 합계로 표시하고 0원이라고 간주하지 않습니다. mL 필요량은 기존 사용자 확인값을 유지합니다.
3. `price-reference.js` 및 비교 템플릿: 비교 화면의 조사 예산 카드 목록을 없애고 수집된 실제 판매상품만 보여줍니다. 장보기에서 조사 예산을 확인할 수 있다는 안내를 제공합니다. API/조사 데이터 자체를 삭제하지 않습니다.
4. `product-offers.js`: 실시간 조회 상품에 '비교 목록에 추가' 버튼을 추가합니다. 조회 상품명·판매처·포장량·단위·가격·주소·조회시각을 비교 목록으로 넘깁니다. 규격 미확인은 사용자가 입력하고 확인 체크해야 합니다. 단위 불일치는 계속 차단합니다.
5. `ingredient-purchase.js`: 실제 상품 비교 목록을 기본 표시합니다. 재조회한 같은 상품/주소는 중복 추가 대신 갱신합니다. 확인한 배송비·무료배송 기준을 목록에서 입력해 총지출을 비교할 수 있습니다. 미확인 배송비를 무료로 처리하지 않습니다. 무료배송 기준은 필요량 환산가가 아닌 포장 구매금액으로 판정합니다.
6. 실시간 조회에서 받은 후보만 기존 확인ID를 사용하는 저장 콜백을 제공합니다. 장보기 재료에서 들어온 경우 비교 목록에서 상품 구성 확인 체크 후 선택·저장할 수 있습니다. 비교 목록에 추가하는 것 자체는 저장이 아닙니다. 직접 입력한 상품은 비교용이며 인증된 구매상품으로 저장하지 않습니다.
7. 수동 입력 폼은 기본 접힘으로 바꾸고 100g/100ml 정렬 문구를 선택 단위에 맞춰 바꿉니다. 단위나 재료를 변경하면 이전 비교 목록을 비워 오비교를 막습니다.
8. 관련 화면/모듈 캐시 버전을 갱신합니다. 기존 백엔드 회원 격리·확인ID·단위 검증·멱등 저장 API, 수집 스케줄·판매처·Gemini/Grounding 동작은 변경하지 않습니다. MySQL/SQLite 추가 스키마 변경도 없습니다.

## 사용 순서
1. ZIP은 256~258 누적본입니다. 서버를 중지하고 프로젝트 최상위에 폴더 구조 그대로 덮어쓴 뒤 재시작·화면 새로고침합니다. 데이터 파일이나 인증키는 포함하지 않습니다.
2. 내 장보기에서 재료의 '이 재료 가격 비교'를 누릅니다. 이 진입 경로로 들어와야 기존 장보기 항목에 상품을 선택·저장할 수 있습니다.
3. 단위·필요량을 확인하고 판매처 상품을 조회합니다. mL로 바꿀 때 g를 환산하지 말고 확인한 부피를 입력합니다.
4. 원하는 상품의 '비교 목록에 추가'를 누릅니다. 정기 저장 카드의 '이 상품명으로 조회·선택'은 기존처럼 실시간 조회를 열며, 조회된 카드에서 비교 목록에 추가합니다.
5. 비교 목록에서 단가·포장 구매금액·잔량을 비교합니다. 배송비가 확인됐으면 금액을 입력합니다. 무료배송 확정은 0, 미확인은 빈칸입니다.
6. 상품 구성을 확인하고 체크한 뒤 '이 상품 선택·저장'을 누릅니다. 기존 서버 확인 요청을 거쳐야 저장됩니다. 배송비 입력값은 현재 비교를 위한 값이며 기존 장보기 구매금액 합계는 계속 배송비 미포함입니다.
7. 내 장보기에서 KAMIS·참가격 기준 예상금액과 선택 상품 구매금액을 따로 확인합니다.

비교 목록(자동/수동 후보와 배송비 입력)은 현재 화면의 임시 자료입니다. 새로고침하면 사라집니다. 서버에 명시적으로 선택·저장한 구매상품은 기존 저장 방식대로 유지됩니다.

## 실제 검증
- Python 57건 통과. 기존 수집·스케줄·단위·저장 회귀 유지.
- Java 21 DB→TSV→실제 가격 조회/상품 생성자 격리 하네스 통과(기존 검증 범위).
- 관련 Node 테스트 41건 통과. 자동 조회→비교 추가·중복 갱신·단위 정렬·불일치 차단·배송비/무료배송 계산·명시적 선택 콜백·실제 product-offers JS의 확인ID 저장 요청·조사 예산/구매금액 분리·비교 화면에서 조사 카드 미표시를 포함합니다.
- JS 문법 검사와 수정 비교 HTML의 태그 중첩 검사 통과.
- 전체 Gradle/Spring Boot 기동·실제 로그인 브라우저·운영 DB 저장·외부 판매처/Gemini 실호출은 이 환경에서 미검증입니다. UI 검증은 실제 JS와 모의 DOM/API입니다. 운영 DB 원본은 변경하지 않았습니다.
