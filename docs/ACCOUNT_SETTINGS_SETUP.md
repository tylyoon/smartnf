# 회원정보·계정 설정과 일자별 관리 예시 적용

## 적용

1. 기존 프로젝트와 개발 DB를 백업합니다. 기존 실행 서버를 Ctrl+C로 종료합니다.
2. ZIP의 파일을 프로젝트 루트에 같은 경로로 덮어씁니다. 외부 smartnf 폴더는 없습니다. 이번 ZIP은 직전 React 개인 MyPage ZIP을 적용한 상태가 기준입니다.
3. 프로젝트 루트에서 실행합니다.

```bash
bash ./gradlew test --no-daemon
```

4. 성공 후 실행합니다.

```bash
bash run_local.sh
```

5. MySQL에서 V7 적용을 확인합니다. 수동 CREATE/repair/이전 Flyway 파일 수정은 하지 않습니다.

```sql
USE smartnf;
SELECT version, description, success FROM flyway_schema_history ORDER BY installed_rank;
SHOW COLUMNS FROM members LIKE 'auth_version';
SHOW TABLES LIKE 'member_email_changes';
```

V7 `add account settings`, success=1이어야 합니다. 이번 작업은 DB 구조와 인증 검사를 함께 바꾸므로 일부 파일만 적용하지 마세요. 실패하면 오류 부분을 공유하고 비밀번호/환경 파일 전체는 보내지 마세요.

## 화면 확인

- 로그인 → http://localhost:8080/mypage → **회원정보·계정 설정** / **일자별 관리 예시** 링크.
- 계정 화면 직접 주소: http://localhost:8080/mypage/account
- 예시 직접 주소: http://localhost:8080/mypage/examples
- 화면이 예전 상태면 Ctrl+F5를 누릅니다. 번들이 포함되어 일반 적용에는 Node 빌드가 필요 없습니다.
- 5개 예시를 선택하며 날짜별 혈압/체중/메모·미기록·재시작 표시를 확인합니다. 실제 계정으로 복사하거나 저장하는 버튼이 없는 것이 정상입니다.

## 계정 기능 검사 — 삭제해도 되는 가상 일반 계정으로

1. 회원정보·SNS 연결 상태가 로그인한 본인 계정과 맞는지 확인합니다. 다른 SNS로 별도 가입했다면 같은 회원으로 자동 병합되지 않습니다.
2. 일반 이메일 계정에서 현재 비밀번호를 틀리게 입력하면 변경되지 않아야 합니다. 15분 내 5회 실패하면 계정 변경 본인 확인이 해당 기간 제한됩니다.
3. 새 비밀번호를 바꾸면 현재 로그아웃됩니다. 이전 비밀번호로 로그인할 수 없고 새 비밀번호로 로그인되어야 합니다. 다른 브라우저에 열어둔 같은 회원의 이전 세션도 다음 요청부터 차단되어야 합니다.
4. 탈퇴 검사는 반드시 버려도 되는 가상 계정으로 하세요. 확인 체크와 `회원탈퇴` 문구·현재 비밀번호가 필요합니다. 건강기록·카드 구성·로그인 자격은 삭제됩니다. 다른 회원 기록은 유지되어야 합니다.
5. 최소 회원 ID·탈퇴 상태·동의 이력은 남습니다. 운영용 전체 삭제/보관·백업 처리가 완성됐다는 의미는 아닙니다.
6. SNS 전용 계정은 연결 상태만 확인합니다. 이메일/비밀번호 변경은 SNS에서 관리하며, SmartNF 회원 탈퇴는 공급자 본인 재확인 연결 전까지 제한됩니다. 건강기록만 삭제하려면 기존 저장 동의 철회를 이용합니다.
7. 관리자 계정은 별도 이관 절차가 필요하여 탈퇴할 수 없습니다.

## 이메일 변경을 쓰려면 — SMTP 설정 필요

보안상 현재 비밀번호와 **기존·새 이메일 두 곳의 소유 확인**을 요구합니다. 확인 전에는 기존 이메일이 유지됩니다. 메일 설정 전에는 폼이 숨겨지고 설정 필요 안내가 표시됩니다.

개발 PC의 기존 `.env.local`에 아래 **설정명**을 추가할 수 있습니다. 실제 값을 채운 파일은 공유하거나 Git에 올리지 마세요. 공개 배포에서는 환경 비밀 설정을 사용합니다.

```dotenv
SMARTNF_ACCOUNT_MAIL_ENABLED=true
SMARTNF_ACCOUNT_MAIL_FROM=발송서비스에서_허용된_발신주소
SMARTNF_SMTP_HOST=메일서비스_SMTP_호스트
SMARTNF_SMTP_PORT=587
SMARTNF_SMTP_USERNAME=SMTP_인증계정
SMARTNF_SMTP_PASSWORD=SMTP_전용비밀번호
```

- STARTTLS를 필수로 사용합니다. 공급자가 STARTTLS/587을 지원하는지 확인해야 합니다. SSL 전용 465 설정을 이 예시와 혼용하지 마세요.
- 공급자별 SMTP 허용·앱 비밀번호·발신 주소 인증이 필요할 수 있습니다. 실제 서비스/계정이 정해지면 해당 공식 설정을 확인합니다. 이번 작업에서 실제 SMTP 계정 설정·메일 발송은 하지 않았습니다.
- `bash run_local.sh` 재실행 후 로그인하여 메일 준비 상태를 확인합니다. 서버 설정만으로 실제 전달 성공을 보장하지 않습니다.
- 기존·새 주소 모두 실제 수신 가능한 개발 테스트용 주소를 사용합니다. 서로 다른 22자 코드를 받아 **현재 비밀번호 + 기존 코드 + 새 코드**를 입력해야 변경됩니다. 코드는 타인에게 보내지 마세요.
- 만료 10분·최대 5회 코드 확인·재발송 60초 제한. 성공 후 두 코드는 폐기됩니다. 다시 로그인할 때 새 이메일을 사용합니다.
- 메일 발송 실패·잘못된 코드·만료·메일 중복일 때 기존 로그인 이메일이 유지되어야 합니다. 예외 메시지에 SMTP 비밀번호/확인 코드를 첨부하지 마세요.
- 메일이 필요 없으면 기본값을 유지하거나 `SMARTNF_ACCOUNT_MAIL_ENABLED=false`로 둡니다. 예시·계정 조회·일반 비밀번호 변경은 계속 이용할 수 있습니다.
