# 198절 검색 입력 도우미와 일부 영양 그래프

검색 기준 → 기준 입력란 → 자체 입력 도우미 → 내 취향 반영 → Gemini 동의 → 추천 순서로 화면을 변경했다. 도우미는 검색 기준을 임의로 바꾸지 않고 선택한 기준에만 결과를 적용한다.

재료/음식명은 기존 로컬 LLM의 normalize API를 사용한다. 음식명은 한 개만 받고, 재료는 이름과 원문 분량을 유지한다. 음식으로만 확인된 항목을 재료에 잘못 넣지 않는다. 스파게티처럼 분량 없는 대표 음식명은 명시적인 보조 규칙도 사용한다. 실제 식재료의 모든 이름을 구분하는 범용 사전은 아니다.

열량 목표와 질환 조건에는 음식 파서 모델을 억지로 사용하지 않는다. 브라우저에서 사용자가 명시한 수치·알려진 항목 별칭·명시적인 재료 제외만 확인해 적용 전 표시한다. 열량 목표를 추정하거나 일일 열량을 한 끼로 변환하지 않는다. 숫자 범위/여러 상한/상한이 아닌 목표는 재입력을 안내한다. 임의의 질환명은 원문으로 ‘기타’에 적용하고 사용자가 확인한다. 진단·식사 제한·의료 판단 기능이 아니다. 기존 식사 기준/메모의 전달 범위는 변경하지 않는다.

검색 기준 전환은 입력 초기화가 아니라 빈 목적지 입력란으로 바뀌는 현상이었다. 각 입력을 보존하고 재료↔음식명 전환 시 목적지가 비었을 때만 길이를 확인해 이전 값을 복사한다. 원문·취향 선택도 유지한다. 기준 전환 또는 도우미 원문 수정은 해석 결과를 무효화하고 늦은 응답을 적용하지 않는다. 도우미 입력에서 Enter는 정리 동작이며 추천 폼을 제출하지 않는다.

food-studio-core.js는 187절 물 ml 수정본을 기준으로 renderBars만 변경했다. 일부 합계의 막대를 0%로 숨기던 코드를 제거하고 점선·줄무늬 표시와 자료 포함 개수, 전체 값이 아니라는 범례를 추가했다. 실제 숫자가 없는 항목은 막대를 만들지 않는다. 일부 막대는 확인된 재료의 합계이며 전체 값/영양 우열로 해석하지 않도록 안내한다. 스타일은 추천과 시뮬레이터에 함께 연결한다.

이번 범위에서는 서버·DB·취향 추천 생성 조건·MyRecipe 화면·단일/다중 음식 이동 방식을 변경하지 않는다. 과거 여러 음식 선택 관련 논의와 별개의 검색/그래프 수정이다.

검증: 실제 프런트엔드 JS와 HTML을 JSDOM에서 실행해 기준 우선 배치, 음식명 스파게티 적용, 음식명을 재료에 잘못 적용하는 경우 안내, 재료/음식명 값 보존, 4가지 기준 도우미, explicit kcal 범위/일일 목표 거부, 동의 초기화, 2/4 재료·50값이 최대100 축에서50% 점선 막대가 되는지, 미확인 값이 자료 부족으로 유지되는지 확인했다. 변경 JS 문법 검사 통과. 실제 Qwen/Gemini 응답 품질과 브라우저 시각 검사는 미실행이다. 서버 미변경으로 Java/DB 검사를 반복하지 않았다.
