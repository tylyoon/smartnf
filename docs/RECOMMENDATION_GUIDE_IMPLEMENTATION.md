## 확보 자료와 연결 방식
- 고혈압: 질병관리청 ‘장볼 때 체크리스트’에서 이름이 확인된 채소·곡류·과일·생선/새우와 일반 두부를 대조. 저지방·무가당·무염처럼 제품 확인이 필요한 용어를 일반 제품에 자동 부여하지 않음.
- 이상지질혈증: 질병관리청 식사 방향, 병원 자료의 현미·보리/채소/두부 설명과 원본 분류를 대조. 채소의 구체적인 명칭은 별도로 확인한 장보기 예시와 대조한 제한된 범위임을 명시. 모든 어패류를 저지방 어육류로 분류하지 않음.
- 당뇨병: 질병관리청 식품교환표 예시의 오이·시금치·양송이버섯만 1차 연결. 원문의 교환량을 원본 생것 중량이나 개인 권장량으로 전용하지 않음. 당근 등 별도 주의가 있는 식품은 이번 범위에서 제외.
- 감량: 전문기관의 채소 선택 방향과 구체적 식재료 분류를 함께 확인한 제한된 채소만 연결. ‘다이어트에 좋은 모든 식품’ 목록이나 적정 열량을 산출한 것이 아님.
- 저지방 어육류: 학회 공개 문서에서 지방별 교환군 정의를 추가 확인했지만, 웹 추출 텍스트에서 일부 이미지의 군 경계가 불명확하여 개별 품목의 지방군·교환량을 코드에 확정하지 않음.

식품군 방향 → 원재료 분류 → 원본 이름·상태 대조는 SmartNF의 연결 규칙입니다. 원문 기관이 해당 식품코드를 직접 추천했다는 뜻이 아닙니다. 코드별 연결 경로는 `selection_rules_v1.json` 및 생성 JSON의 `rule_ids/evidence`에 남깁니다.

## 추천 전에 확인하는 조건
건강정보의 확정본만 사용합니다. 추천 페이지에 별도 관리조건 양식을 추가하지 않습니다.

- 만 19세 이상이며 비교 기준이 ‘일반 성인 참고’인 경우만 적용. 19세는 현재 구현 범위 제한이며 임상적 안전성을 판정하는 기준이 아님.
- 건강정보에서 진단받은 질환 항목을 확인한 경우에 사용. 현재는 고혈압·이상지질혈증·당뇨병 및 감량 목표를 연결.
- 신장질환 또는 기타 만성질환을 함께 선택하면 나머지 질환도 통합 보류. 기타 체크만으로 지방간/통풍을 추측하지 않음.
- 현재 버전은 치료·복약 중이거나 복약 미확인이면 보류. 약물 정보를 자동 해석하거나 복약을 변경하도록 안내하지 않음.
- 의료진 식사·운동 제한에 ‘없음/해당 없음/제한 없음’으로 본인이 확인한 경우만 진행. 공란을 제한 없음으로 취급하지 않음. 자유서술 제한·증상·치료 내용이 있으면 보류.
- 알레르기 ‘없음’ 또는 지원하는 원재료 항목을 본인이 확인·적용한 경우만 진행. 미입력/기타/아황산류/검토 상태는 보류.
- 감량 목표는 키·체중 유효성과 저체중 여부(BMI18.5 미만 시 보류)만 확인. 필요 열량/감량 속도/개인 적합성 산정 없음. 체중 지표 참고: https://chs.kdca.go.kr/cdhs/biz/pblcVis/pop_idx.do?visIdxSn=10
- 실제 질환·복약·제한을 숨기거나 다른 값으로 바꾸어 추천을 열도록 안내하지 않습니다. 해당하는 상태를 그대로 입력하면 보류 사유가 표시됩니다.

## 자료와 화면의 보호 규칙
- 국표 식품코드·원본 이름·군·분석 상태·기준량 대조. 소금첨가/양념/자반/젓갈/훈제/가루/통조림 등과 원문 범위 밖 상태 제외. 생선 알/내장을 일반 생선 살코기로 연결하지 않음.
- 필요한 영양값은 numeric 상태만 후보 연결에 사용. 공란을0으로 만들지 않음. 영양표는 실제 100g 값이며 개인 권장분량이나 식품교환 단위가 아님.
- 후보 선택 시에도 최신 코드/원본 영양값/알레르기를 다시 확인. 자료 버전 불일치나 로드 실패 시 후보를 표시하지 않고 다시 불러오기 제공.
- 알레르기는 기존 원재료 판별 규칙을 그대로 사용. 알레르기 조건이 있으면 단일 원재료 확인 불가 품목도 제외. 교차접촉/제품 첨가물까지 확인한 안전 보증 아님.
- 두 번째 클릭은 선택 해제. 나의 선택 식품에서도 제거. 해제한 카드는 이번 추천 화면에서 숨기며 새로고침하면 다시 조회 가능. 분류 버튼도 재클릭 시 전체로 돌아옴.
- 이미 확정 등록한 항목은 임시 선택과 별도로 유지. 확정 목록/DB/MyPage를 이번 작업에서 변경하지 않음.

## 적용 및 확인
1. ZIP의 src/python/docs를 기존 smartnf 루트에 병합합니다. 최신 영양 데이터와 추천 JSON도 함께 동봉되어 Python 재실행은 필요 없습니다.
2. 서버 종료 후 `bash run_local.sh`, 브라우저 Ctrl+F5.
3. 건강정보에서 **본인의 실제 조건**을 확인하고 건강정보를 확정합니다. 알레르기는 별도 조건 적용 값을 사용합니다.
4. http://localhost:8080/preview/health/recommendations 접속. 지원 범위면 추천 이유/출처/영양값이, 보류 범위면 구체적 사유가 표시됩니다.
5. 분류 선택 → 식품 담기 → 나의 선택 식품 표시 → 다시 눌러 해제 → 목록/카드 제거를 확인합니다.

기능 시험은 허구의 ‘일반 성인, 45세, 고혈압, 치료·복약 해당 없음, 제한 없음, 알레르기 없음’ 데이터로 수행했습니다. 실제 사용자 상태를 이 값으로 바꾸라는 뜻이 아닙니다.
