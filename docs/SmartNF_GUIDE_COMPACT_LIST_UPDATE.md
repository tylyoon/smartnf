# 건강별 식품 가이드 · 기준 그래프와 목록 탐색 개선

2026-11-04 / 직전 SmartNF_HEALTH_GUIDE_COMPARE_UPDATE.zip 적용 프로젝트 기준.

## 변경

- ‘나의 관리 목적’을 **‘나의 관리 항목’**으로 변경.
- 2번 오른쪽 일반 기준·질환별 관리 기준을 실제 가로 막대로 표시. 같은 단위의 고정 기준은 같은 눈금을 사용하며, 수치가 같으면 ‘동일 수치’로 표시한다. 포화지방 총열량 7% 기준은 g으로 환산하지 않고 별도 0~100% 눈금으로 표시한다. 고정 수치가 없는 항목은 문구를 유지하고 0이나 임의 비율을 그리지 않는다.
- 3번 긴 식품 카드를 **식품명·분류·참고 레시피 유무의 짧은 행**으로 교체. 목록 높이는 PC 최대 600px, 모바일 최대 470px이며 20건씩 페이지를 나눈다. 검색·분류·페이지 이동을 유지한다.
- 행을 클릭하면 우측 상세에 원자료 기준량·영양 비교·선택 버튼·레시피/재료 선택·출처/연결 근거를 표시. 목록 조회와 담기는 분리한다. 담기·해제할 때 전체 목록을 다시 그리지 않아 위치와 상세를 유지한다. 모바일에서는 기존 하단 패널을 유지한다.
- **기존 식재료·식품 영양정보와 같은 SmartNFDishRecipes.mount/commit/grouped/exportItems 기능**으로 레시피의 재료를 직접 연결한다. 나의 선택 식재료에 음식별 묶음으로 표시하고 재료 선택·제외와 MyPage 저장에 연결한다. 음식/레시피와 재료의 출처·원문 버전을 유지한다.
- 레시피가 없으면 ‘참고 레시피 미연결’로 표시하고 임의 재료 추론을 하지 않는다. 자료 로딩 실패와 미연결을 구분한다. 참고 레시피의 재료 선택은 음식 영양값을 재계산하지 않으며 음식의 실제 배합/알레르기 안전성 확인을 뜻하지 않는다.

## 적용

1. 서버 종료(Ctrl+C).
2. ZIP 내부 `src`, `docs`를 프로젝트 루트에 병합.
3. **`bash run_local.sh`** 실행. 이 스크립트가 `.env.local`의 DB/Flyway/SNS 설정을 읽는다. `bootRun` 직접 실행으로 대신하지 않는다.
4. 브라우저 Ctrl+F5.

이번 변경에 새 DB migration이나 React 번들은 없다. npm 빌드·자료 재수집·가상 데이터 재생성은 필요 없다. 직전 업데이트의 V13 적용 상태는 유지한다. 기존 음식·레시피 연결 기능 및 데이터가 적용된 프로젝트를 전제로 하며 공유 레시피/선택/저장 모듈은 이번 ZIP에서 교체하지 않는다.

## 화면 확인

- 1번 제목 ‘나의 관리 항목’ 확인.
- 혈압 관리 선택 → 2번 나트륨 일반/질환 기준 두 막대와 동일 수치 표시 확인.
- 혈중 지질 관리 선택 → 포화지방 g/총열량 % 눈금이 구분되는지 확인.
- 3번 참고 레시피 탭 → 100건 이상 후보를 짧은 목록·20건 페이지로 확인.
- 식품 행 선택 → 우측 상세 조회 → 나의 선택에 담기 → 레시피 버튼 → 재료 체크 → 연결.
- 4번 선택 식재료의 음식별 재료 묶음에서 선택·제외 확인. 날짜·계획 종류를 확인하고 계정 저장 후 MyPage 건강관리 상세에서 확인.

자동 서버 테스트는 프로젝트 루트에서 `./gradlew.bat test`를 사용한다. 로컬 서버 실행 명령과 구분한다.

- 레시피 원문 버전과 서버 카탈로그의 레시피 버전 일치 확인. 수치/출처/임상 적용 범위를 새로 확장하지 않았다.
- 실제 Spring API/MySQL 저장·재로그인 결과는 이번 가상 API 검증과 별도이며 사용자 환경 확인 대기. 이번 변경은 Java/DB/인증/동의 정책을 변경하지 않았다.
