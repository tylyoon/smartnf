# 장보기 날짜·매장 검색·반복 확인창 개선 (2026-11-05)

## 변경
- 새 장보기/외식 계획 편집에 날짜 입력 추가. 식품 추가/구분 변경으로 다시 그려도 날짜 유지. 선택 날짜의 최신 목록과 revision을 조회해 기존 계획을 보존한 뒤 추가하며 저장 후 해당 날짜를 조회한다. 기존 계획은 기존 날짜 변경/이동 기능을 유지한다.
- 비어 있는 새 계획을 여는 것만으로 dirty로 만들지 않는다. 실제 입력 변경만 편집 취소 확인 대상이다. 취소 확인을 승인하면 편집/dirty/화면/비동기 검색을 즉시 정리한다. 확인 대화상자의 재진입 방지. 취소 응답은 기존 입력을 유지한다.
- 단순 window focus 복귀에서 계획을 자동 재조회하지 않는다. 탭 가시성 복귀 시에도 편집창이 열려 있거나 dirty/pending이면 자동 재조회하지 않는다. 기존 동의 재확인/미저장 이탈 보호/불확실 요청 재시도는 유지한다.
- 주변 매장 검색어에 선택 음식명을 자동 삽입하지 않는다. 상품 검색어는 온라인 장보기에서 유지한다. 온라인 식품명 가져오기도 매장 검색어를 덮어쓰지 않는다. 매장 입력은 지점명/매장명으로 명확하게 표시한다.
- 검색된 매장 마커에는 번호와 매장명을 함께 표시한다. 0건이면 기준 위치만 표시됨과 지점명/지역/거리 재검색을 안내한다. 가짜 지점/좌표 생성이나 조건에 맞지 않는 지점 포함은 하지 않는다. 결과 수/거리·본매장 필터/조회 제한은 유지한다. 선택 음식명이 검색에 섞이는 문제를 수정한 것이며 실시간 네이버 특정 지점 조회 성공을 보장하지 않는다.
- API/DB 스키마 변경, 외부 전송 추가, 개인정보 수집 없음.

## 검증
- Node living-plan-data 4개 통과, 수정 JS3개 문법 검사 통과.
- Chromium: 실제 editor+workspace JS에 대역 계정 API로 날짜 유지/다른 날짜 기존 계획 보존/revision 사용/저장 후 날짜 전환, 취소시 입력 유지/승인시 일회성 초기화/반복 focus에 확인창 없음 확인.
- 실제 place-search JS에 대역 검색 API·지도 SDK로 선택 음식명 없는 매장 요청, 브랜드명 포함 마커, 온라인 상품명 유지/가져오기 분리,0건 기준위치 안내, JS오류 없음 확인.
- 테스트 src/test/browser/shopping-guide.test.cjs. PLAYWRIGHT_PATH/CHROMIUM_PATH 및 필요한 브라우저 라이브러리 경로를 지정해 실행한다. 대역 API 테스트는 사용자 MySQL/실시간 네이버 인증·지점 검색 검증과 구분한다.

## 적용
152절까지 적용한 프로젝트에서 서버 종료→ZIP src/docs 폴더 병합→bash run_local.sh→Ctrl+F5. DB 초기화/마이그레이션 불필요.
새 장보기 계획 추가→날짜/식품 입력→저장→MyPage 날짜 확인. 매장은 트레이더스 선택 후 지점명 비움 상태로 재검색해 결과를 확인한다.
