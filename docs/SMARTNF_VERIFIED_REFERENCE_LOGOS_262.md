# 262. 검증된 판매가 기반 참고금액·사이트 아이콘 (2026-11-17)

사용자 승인에 따라 기존 조사가격만 합산하던 기준을 확장합니다. KAMIS·참가격의 유효한 필요량 예산을 우선하고, 없을 때 검증된 판매 표시가격의 참고금액을 합산합니다.

- HOMEPLUS·OASIS·LOTTE 직접 조회 응답 중 재료 관련성·포장 규격이 확인된 가격만 별도 검증 기록을 남깁니다. Gemini REVIEW와 가격 출처 확인을 분리하며 Grounding·KAKAO 검색 결과를 자동 확정하지 않습니다.
- SQLite offer_price_checks에 확인 기록을 저장하고 verified-sales.tsv로 내보냅니다. 기존 scheduled.tsv 형식과 운영 스케줄은 유지합니다. Java는 상품·URL·판매처·수집시각이 일치하고 24시간 이내인 기록만 참고금액 대상으로 읽습니다.
- 사용자가 확인·저장한 최신 동일 재료 상품도 보완 참고금액으로 사용할 수 있습니다. 오래된 자료와 관련 없는 가공상품은 제외합니다.
- 동일 단위의 확인된 필요량은 비례 계산합니다. 단위가 다르면 g↔mL를 추정하지 않고 1포장(개) 참고금액으로 표시합니다. 후추는 1병 또는 1포장 기준이며 필요량이 한 병을 넘으면 올림합니다.
- 합계에 조사가격/판매가 참고 건수, 포장 기준 건수, 미확인 제외 건수를 표시합니다. 이미 포함한 재료를 선택 상품 구매금액으로 다시 더하지 않습니다. 배송비·쿠폰은 별도입니다. 포장 기준 참고금액과 필요량 비례값의 차액/백분율 비교는 보류합니다.
- 사이트 바로가기의 공백 노드로 생기는 지그재그를 제거하고 균일한 카드로 정렬했습니다. 해당 사이트 origin의 favicon.ico를 공식 아이콘으로 불러옵니다. 실패 시 이름 링크를 유지합니다. 모든 사이트의 가로형 정식 로고 파일 확보·실제 표시 확인은 미완료입니다.

## 실행 검증
Python unittest 59건, 관련 Node 테스트 39건, Java 다중 단위 계약 20건 통과. 실제 Python SQLite 저장 → TSV 내보내기 → 변경 Java 조회 코드 컴파일/실행 통과. Java는 최소 프레임워크 대역을 사용했으므로 전체 Gradle·Spring Boot·MySQL·로그인 브라우저 통합은 미검증입니다. 기존 shopping-storage.test.mjs의 번들 변수명 고정 검사는 기존 실패로 이번 통과 수에 포함하지 않았습니다. HTTP403 실패 테스트는 모의 응답이며 판매처 실접속 성공을 의미하지 않습니다.

## 적용과 운영 자료 확보
ZIP을 프로젝트 루트에 덮어쓰고 서버를 재시작합니다. 261까지 적용한 환경에는 추가 MySQL 마이그레이션이 없습니다. 이전 버전용 V33은 누적 ZIP에 유지됩니다. SQLite 확인 기록 테이블은 수집기 실행 시 자동 생성되며 기존 상품을 삭제하지 않습니다. 기존 17건에는 새 확인 기록이 없으므로 아래처럼 다시 수집하거나 해당 상품을 확인·저장해야 참고금액에 포함됩니다. 실제 수집 결과가 없거나 규격/관련성이 불분명하면 미확인을 유지합니다.

```bash
python tools/price_sources/scheduled_prices.py --collect-now --directory data/price-reference --provider HOMEPLUS --query "올리브오일" --query "소금, 정제염" --query "후추" --query "생크림" --query "우유" --limit 20
```

이번 ZIP에는 운영 DB·TSV·환경변수·비밀키를 넣지 않습니다. 새 코드만 적용해도 실제 판매자료가 자동 생성되는 것은 아닙니다.
