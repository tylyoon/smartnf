# 레이더 확대·축별 실제 단위 눈금/입력값/비교 기준 표시

2026-11-04 / 149절 적용 환경 기준

## 변경
- 기존 모든 축의 ‘사용자÷평균×100’ 공통 눈금을 레이더 도형에서 제거했다. 표에서는 평균 대비 비율을 계속 확인할 수 있다.
- 레이더의 각 축은 실제 단위와 별도 표시 범위를 사용한다. 예: BMI kg/m², 혈압 mmHg, 혈당·지질 mg/dL. 축마다 4개 실제 수치 눈금을 표시한다.
- 축 바깥에 지표/단위, 초록색 내 값, 회색 기준(평균)을 표시한다. 기준은 기존 같은 성별·연령대 NHIS 또래 평균이며 임상 정상 기준이나 개인 치료 목표로 바꾸지 않는다.
- 좌우 분할을 그래프 위/표 아래 구성으로 변경하고 SVG를 크게 확장했다. desktop max1040px, 작은 화면은 그래프 영역만 좌우 스크롤한다.
- 표시용 기본 최댓값을 지표별로 정하고 입력·평균이 범위를 넘으면 해당 축만 여유를 두어 확장한다. 한 지표가 커져도 다른 축의 표시 범위는 바뀌지 않는다. 입력값 자체를 낮추거나 보정·평활화·잘라내지 않는다.
- 표시 범위가 정상 범위가 아님을 명시한다. 축마다 눈금이 다르므로 도형 면적/뾰족함으로 건강을 평가하지 않는다. 원자료·평균·상세 임상 기준은 그대로 유지한다.
- 유효한 입력값은 해당 점으로 표시한다. 평균을 찾을 성별/연령 조건이 없으면 평균 자료 없음으로 안내하고 평균 점·선을 만들지 않는다. 미입력이나 입력 범위 오류의 내 점은 생략하며 0으로 채우거나 누락 축 사이를 잇지 않는다.
- 건강정보/관리항목 저장 흐름·MyPage/API·DB는 이번 변경 대상이 아니다.

## 적용
서버 종료 → ZIP을 프로젝트 루트에 경로대로 덮어쓰기 → bash run_local.sh → Ctrl+F5.

별도 npm 빌드·DB 초기화·마이그레이션 없음.

## 검증
- 기존62개+신규 축 범위2개=64개 Node 테스트 통과. 축별 독립 범위, 큰 사용자/평균 값이 잘리지 않는 확장, 실제 눈금4개 회귀 포함.
- 실제 Spring/Security/Thymeleaf/H2 Chromium에서 큰 단일 지표를 포함한 8개 가상 입력으로 확대 그래프, 실제 눈금32개, 내 값8개/평균8개 숫자와 점을 확인했다. 한 축 확장에도 다른 축 기본 범위 유지 확인.
- 수치1개 누락 시7개 점/6개 연결선/면적 채움 없음, 성별 미선택 시 내 값은 유지/평균점·선 없음, 입력 범위 초과점 제외를 확인했다.
- 1440/1180/800/556/390/320px 페이지 가로 넘침 없음, 모든 축 값·기준 라벨이 SVG 내부에 있음, 작은 화면의 그래프 내부 좌우 스크롤 작동, JS 오류 없음 확인. 확대 그래프 이미지 내부 검토.
- 사용자 MySQL에 접근하지 않았다. 서버 Java 변경이 없어 이전 서버 테스트를 재실행한 것으로 표기하지 않는다.
