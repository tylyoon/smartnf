# MyPage 장보기·외식 계획 적용 안내

2026-11-03 / 직전 `SmartNF_RECIPE_COMPACT_UPDATE.zip`까지 적용한 프로젝트 기준.

## 적용 순서

1. 실행 중인 서버를 종료한다.
2. ZIP의 `src/`, `frontend/`, `scripts/`, `docs/`를 SmartNF 프로젝트 루트에 그대로 덮어쓴다.
3. `bash ./gradlew test --no-daemon`로 검사한다.
4. `bash run_local.sh`로 서버를 실행한다. Flyway **V12 create food plans** 적용을 확인한다.
5. 브라우저에서 Ctrl+F5를 누른다.

기존 MySQL `smartnf_app`/`smartnf` 설정을 그대로 사용한다. 수동 CREATE TABLE, 기존 테이블 삭제/Flyway 초기화는 필요 없다. 번들을 포함하므로 npm 설치/빌드·가상회원/식사 자료 재생성도 필요 없다.

```sql
SELECT version, description, success
FROM smartnf.flyway_schema_history
ORDER BY installed_rank;
```

## 직접 확인하기

1. 계정으로 로그인한다. 영양정보 → 음식·식재료 선택 → 참고 레시피가 있으면 원문 재료를 체크하고 연결한다.
2. 연결 버튼의 **연결 중… → ✓ 재료 N개 연결됨**과 안내/아래 묶음 강조를 확인한다. 이것은 임시 목록 반영이다.
3. 아래 ‘나의 선택 식품’에서 **저장할 날짜·장보기/외식**을 고른다. 외식은 식당/방문 시간, 공통 메모를 선택 입력할 수 있다.
4. 별도의 **장보기·외식 계획 저장 안내**를 읽고 동의한 뒤 **MyPage에 저장**한다. ‘✓ MyPage에 저장됨’과 ‘저장 목록 보기’를 확인한다.
5. MyPage → **장보기·외식 계획**에서 저장 날짜를 누른다. 달력의 장보기/외식 건수와 음식·개별 식재료·음식별 참고 재료를 확인한다.
6. 내용을 바꾸면 ‘저장하지 않은 변경사항’이 표시된다. **변경사항 계정에 저장**을 눌러 반영한다. 다른 날짜로 추가 복사, 날짜 전체 삭제, 식품/참고 재료 제외도 확인한다.
7. 로그아웃했다가 다시 로그인한다. **MyPage의 저장 목록은 유지**된다. 영양정보 화면의 저장 전 임시 선택은 별도이므로 초기화될 수 있다.

첫 저장은 그 날짜에 계획을 추가한다. 같은 영양정보 화면에서 방금 저장한 선택을 수정·저장하면 방금 만든 계획을 갱신한다. 다른 탭이 바꾼 목록은 덮어쓰지 않는다. 다시 연 영양정보 화면은 새 선택이며 기존 계획은 MyPage에서 수정한다.

## 알아둘 범위

- 원자료 출처의 ‘외식’을 사용자의 외식 계획으로 자동 분류하지 않는다. 날짜와 구분은 직접 고른다.
- 계획은 **먹으려는 음식/준비할 식재료**다. 실제 섭취 기록·구매·예약·영양 합계로 자동 변환하지 않는다.
- 참고 재료는 원문과 출처/버전 그대로다. 음식과 같은 조리법이라는 검증, 실제 음식 전체 재료 확정, 영양코드 연결을 뜻하지 않는다.
- 건강정보 동의와 계획 저장 동의는 별도다. 계획 화면의 전용 철회로 모든 계획을 삭제해도 식사·건강 기록과 계정은 유지된다.
- 계획 저장 시 회원 ID는 인증 정보에서 결정하며 다른 계정은 조회·수정할 수 없다. 응답 단절·중복 클릭은 같은 요청으로 재시도하고, 수정 충돌이면 최신 목록을 다시 확인한다.
- 예전 임시 ‘선택 식품 추가 확정’ 자료를 계정 계획으로 자동 이전하지 않는다. 로그인한 상태에서 원자료를 확인하고 새로 저장한다.

DB는 `food_plan_days` → `food_plan_entries` → `food_plan_foods` → `food_plan_ingredients`와 중복 처리용 `food_plan_requests`를 추가한다. V1~V11은 변경하지 않았다.

검증: 전체 Java114개, 관련 JS21개, 기존 프론트엔드17개 통과. 실제 Spring 로그인/H2/Chromium에서 저장·응답 단절 재시도·장보기/외식 달력·복사/삭제·재로그인 복원·계정 분리·수정 충돌·PC/모바일 검증 완료. 사용자 MySQL의 V12 적용과 화면 확인은 별도로 필요하다.

자세한 결정사항·보안·후속 범위는 `SmartNF_IMPROVEMENTS.md` **129절**에 기록했다.
