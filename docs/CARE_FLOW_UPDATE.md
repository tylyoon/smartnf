# 맞춤 관리항목 사용 흐름 정리

## 적용
ZIP 안의 src·docs를 SmartNF 루트에 병합하고 서버 재시작 후 Ctrl+F5로 확인합니다. Python 명령·재수집·DB변경은 필요 없습니다.

## 확인 순서
1. 건강정보 → 맞춤 관리 항목. 비교평가 결과 / 이유 / 실천항목의3열을 확인합니다. 모바일은 세로 배치입니다.
2. 혈압 선택 → 짜게 먹는 습관 줄이기를 체크합니다. 상단에 즉시 카드가 생기며 미확정으로 표시됩니다. 다시 체크를 해제하면 사라집니다.
3. 혈압과 혈중 지질에서 균형 잡힌 식사를 각각 선택합니다. 카드는1개이고 관련 평가태그는2개입니다. 한 분야 해제는 해당 태그만, 전체분야 해제는 카드를 제거합니다.
4. 선택한 관리항목 확정을 누릅니다. 확정 상태와 식품 선택 가이드 이동 버튼이 표시됩니다. 예시는 예시로 구분합니다.
5. 식품 가이드에서 전달된 항목을 확인한 뒤 건강정보로 돌아옵니다. 유효 확정 목록은 복원됩니다.
6. 상단의 관리항목 제외를 누릅니다. 카드가 없어지고 이전 전달이 해제됩니다. 남은 항목을 다시 확정해야 전달됩니다.
7. 미확정 상태에서 새로고침하면 초안은 복원하지 않습니다. 확정 후 새로고침하면 유효 목록을 복원합니다. ‘선택 수정’ 버튼만 누르는 것은 확정본을 지우지 않습니다.
8. 내 입력을 작성/수정한 경우 나의 상태에서 건강정보를 확정하고 관리항목을 다시 확인합니다. 미입력 수치는 강제로 채우지 않습니다. 알레르기 조건은 기존 별도 적용 흐름을 유지합니다.

## 상태와 전달
- 미확정: 현재 화면 선택. 상단 목록은 바로 갱신하지만 페이지 전달 데이터로 자동 저장하지 않습니다.
- 확정: 행동ID와 직접 선택한 평가분야만 같은 탭 최대24시간 전달. 기존 sessionStorage 키/version1 계약 유지.
- 수정/평가조건 변경: 이전 전달을 해제하고 재확정 필요 상태로 표시. 항목을 임의 삭제하거나 확정 성공으로 표시하지 않음.
- 전달 실패/만료: 직접 연결 버튼을 제공하지 않거나 이동을 중단하고 안내합니다. 저장소 차단 상태에서는 오류를 해결한 뒤 진행합니다.
- 식품 임시 선택과 추가 확정 등록은 별도 상태이므로 이 작업에서 이미 선택한 식품을 일괄 삭제하지 않습니다.

## 구현
`draft-state.js`의 SmartNFCareState가 유효성·만료·건강정보버전·확정/해제를 공통 관리합니다. 기존 임시식품 초기화 정책은 유지합니다. `food-flow.js`는 공통 상태를 읽고, `food-choice.js`는 변경 이벤트를 반영합니다. `health-guide.js`는 현재 선택과 확정 상태를 구분해 표시합니다. `healthcare-ui.js`는 확정 관리항목 수를 공통으로 표시합니다.

## 유지한 범위
기존 공식 실천 안내·출처·평가 기준·레이더·회원보안·지도 API·알레르기 제외 규칙은 변경하지 않았습니다. 이번은 Frontend 상태/연결 보완이며 회원 DB 저장이나 MyPage 등록 완료가 아닙니다.

## 후속
- MyPage: 회원별 관리항목 등록/삭제·실천기록·이력/피드백을 해당 페이지 작업 때 구현.
- Backend: 공통 행동/분야 계약과 검증을 서버로 이동, 회원 소유권/저장/삭제·원자적 갱신.
- Python: 기존 근거 수집/품질 검토/갱신 이력 관리 유지. 신규 수집 작업 없음.

## 검증
실제 HTML/JS 브라우저 검사로 선택·해제/다분야 연결·복원·명시확정·식품페이지 전달·건강정보수정·만료·저장실패·320/390/1440폭 확인. 서버/MySQL 실연결은 사용자 로컬 적용 후 확인합니다.
