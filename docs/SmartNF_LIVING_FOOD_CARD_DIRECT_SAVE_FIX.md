# 식품 하나당 카드 하나·직접 계획 저장 (2026-11-05)

## 요청 재해석과 수정
이전155절은 목록 카드에 음식들을 묶고 별도의 체크박스로 재선택하도록 해 요청한 선택 단위를 잘못 구현했다. 이제 원래 MyPage 목록은 그대로 두고 조회용 카드만 음식·식재료 하나당 하나로 펼친다.
- 카드 제목은 음식명, 아래에 원래 일반/건강관리·질환명/목록 구분 표시. 클릭=선택, 재클릭=해제, 여러 선택/전체 선택·해제 유지. 별도 음식 체크박스 줄 제거.
- 선택 키는 원래 목록 인덱스+식품ID. 같은 음식이 다른 건강관리 목록에 있어도 혼합하지 않는다. 안내/조리법/외식 음식은 클릭한 카드의 식품만 표시. 제목과 선택 개수는 식품 기준으로 통일.
- 장보기·외식 계획 저장 클릭은 추가 confirm 없이 기존 저장 흐름 실행. 날짜 입력만으로 저장하지 않는다. 진행/완료/오류는 화면에 표시. 응답 불확실 후 결과 재조회 확인 및 실제 저장중 이탈 보호는 별도 유지.
- 기존 MyPage move API 사용. 같은 원래 목록에서 고른 식품들은 한 작업으로 묶어 이동하고, 다른 원래 목록/질환은 구분해 역순 처리. 미선택 음식·목적날짜 기존 계획/연결재료/질환 구분 보존. DB/API schema 변경 없음.

## 검증
- 두 음식이 있는 같은 원래 목록에서 카드 하나 선택→외식 h4/조리 summary 각1개, 제목 선택 식품1개, 별도 체크박스 줄0 확인.
- Chromium 실제 guide/editor/stage-save JS+대역 API: 단일/복수 음식 필터와 단계 유지, 저장 confirm 호출0, 날짜 계획 이동·미선택 잔여/목적 기존 목록·관리구분/연결재료 유지, 응답 유실 동일 UUID본문 재시도/중복없음, 진행 잠금/5폭/JS오류 없음 통과. Node 데이터4개/JS문법 통과.
- 실제 사용자 MySQL 저장 확인과 구분한다. 기존 다중선택 테스트 진입점은 새 음식카드 회귀 테스트로 연결해 이전 묶음카드 전제를 제거했다.

## 적용
155절 적용 프로젝트 서버 종료→ZIP src/docs 병합→bash run_local.sh→Ctrl+F5. DB 초기화/마이그레이션 없음.
해물칼국수/짬뽕은 별도 카드로 표시되어야 한다. 하나만 클릭하면 아래에도 해당 음식만 나오며, 날짜+계획 저장을 누르면 추가 확인 팝업 없이 저장한다. 저장 성공 후 MyPage 해당 날짜에서 확인한다.
