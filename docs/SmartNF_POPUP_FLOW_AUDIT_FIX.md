# 프로젝트 저장·이동 팝업 점검 및 개선 (2026-11-05)

## 점검 범위
현재 전달본의 MyPage React 원본 및 빌드 결과, 헬스케어/식품선택/건강 식생활 가이드 클라이언트 JS와 관련 HTML에서 alert/confirm/prompt/beforeunload 호출을 점검했다. 도메인 함수명인 draft-state.confirm/food-registration.confirm은 브라우저 팝업이 아니므로 유지한다. 실제 로그인 제공자 인증 화면·명시적 외부 링크와 달력 입력 UI는 임의 제거하지 않는다.

## 결과와 정책
| 화면/동작 | 변경 후 |
|---|---|
| MyPage 같은 날짜의 전체/장보기/외식 표시 전환 | 재조회하지 않고 보기만 변경. 수정 내용 유지·확인창 없음 |
| MyPage 계획 저장 후/아무것도 수정하지 않은 조회 | 저장 가능한 필드 기준으로 변경 비교. 미저장 오인 방지 |
| 건강정보 수정 화면만 열기/값 원복/변경 없는 취소 | dirty 아님. 화면을 열었다는 이유만으로 이탈·탭 경고 없음 |
| 실제 계획·식사·일일 기록·건강정보 변경을 버리는 날짜/화면 이동 | 기존 미저장 이탈 보호 유지 |
| MyPage 계획 추가 복사/가이드 저장·이동 | 명시적 버튼 클릭으로 실행, 중복 브라우저 확인 없음 |
| 계획/식사/일일 기록 삭제, 건강정보·계획 동의 철회와 전체 삭제 | 화면 안에서 확인/취소. 취소시 요청 없음·확인시 실행 |
| 이전 형식 식사 재저장, 임시 건강정보 불러오기, 빈 관리항목 저장, 저장 결과 재조회 | 필요한 설명과 선택을 화면 안에서 제공 |
| 저장 중/결과 불확실 요청에서 페이지 이탈 | 결과 유실·중복 방지 보호 유지. 일괄 팝업 무력화 없음 |

## 구현
- 공용 action-confirm.js는 모달/overlay/window.confirm 없이 현재 화면 안에 설명과 확인/취소 버튼을 붙인다. textContent로 메시지 출력. Escape 취소, 포커스 반환, 대상/화면이 사라지면 취소한다. 날짜/최신본 조회에서도 이전 확인을 취소해 과거 화면의 작업이 실행되지 않게 한다.
- 계획 dirty는 API 입력 형태를 비교하여 이름/원자료 표시 등 비저장 메타데이터 차이를 제외한다. 같은 날짜의 달력 종류 클릭은 현재 draft를 유지한다.
- 건강정보의 onDirty/beforeunload/모드 전환은 실제 값 차이·불확실 요청 기준. 수정 화면을 열었다는 이유로는 경고하지 않는다. 편집 중 외부 포커스 복귀에 원래 입력을 덮어쓰지 않는 기존 보호 유지.
- 식사/일일 기록도 같은 날짜 선택은 입력을 유지. 전체 날짜 전환의 진짜 변경 폐기 보호는 유지한다.
- API·DB 스키마/회원·MyPage 라우팅·원본 기록 변경 없음. 전역 confirm/alert 덮어쓰기 없음. 삭제/철회의 확인을 생략한 것이 아니라 화면 안으로 이동했다.

## 검증
- MyPage 프로덕션 번들 빌드 성공. 관련 Node7개 및 수정 JS문법 통과.
- 실제 React FoodPlans/MyHealth를 Chromium에서 실행: 정상 조회/같은 날짜 필터 팝업0·수정 유지, 실제 수정 후 다른 날짜 이동은 경고/취소 입력 유지, 저장 후 dirty 해제, 삭제 inline 취소 요청0/확인시 요청1, 확인중 날짜이동은 이전 확인 취소, 건강정보 열기·원복·변경없는 취소 경고0/실제 변경 경고 유지. JS오류 없음.
- 실제 가이드 JS 저장·이동 회귀: 개별 음식/잔여·목적 계획 보존, 저장 팝업0, 응답 유실 동일 요청 재시도/중복없음·잠금·5폭·JS오류 없음 통과.
- API는 대역으로 검증했다. 사용자 PC MySQL/실서비스 계정 전체 검증과 구분한다. 범위 안 원본을 재검색하여 남은 native confirm이 실제 미저장 변경 폐기 경로임을 확인. 모든 화면의 모든 수동 조합을 실계정으로 검증했다고 확대하지 않는다.

## 적용
157절 적용 프로젝트에서 서버 종료→ZIP src/docs/frontend 병합→bash run_local.sh→Ctrl+F5. 빌드된 personal-mypage.js 포함으로 사용자 npm 빌드 불필요. DB 초기화/마이그레이션 없음.
검증 재현: frontend/test/popup-entry.jsx를 esbuild로 /tmp/popup-test-bundle.js에 bundle하고 src/test/browser/popup-audit.test.cjs 실행. 브라우저 경로/PLAYWRIGHT_PATH/필요한 LD_LIBRARY_PATH는 환경에 맞게 지정한다.
