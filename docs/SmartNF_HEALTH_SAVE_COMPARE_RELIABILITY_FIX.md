# 건강정보·관리항목 저장/비교 표시 재수정

2026-11-04 / 148절 적용 환경 기준

## 실제 보고와 원인
사용자 보고: 나이/성별 입력칸 불일치, 관리항목 액션/안내 배치 불량, 관리항목 저장 차단과 MyPage 빈 상태, 레이더 사용자 점·선 누락, 가로 그래프 참고선 없음. 이전 검증이 측정일/일반 성인 조건이 채워진 사례 위주여서 실제 스크린샷의 빈 조건과 저장 동선을 놓쳤다.

- 나이/성별은 같은 행에서 성별 아래 설명문이 label 크기에 영향을 줬다.
- 관리항목은 건강정보 변경 감지 시 앞 화면에서 먼저 저장하라고 차단했다.
- 레이더의 산술 비교까지 기존 임상 평가 badge가 pending이면 막았다.
- 가로 그래프도 pending이면 기존 참고선을 숨겼다.

## 수정
1. 성별 설명을 입력칸 밖으로 이동하고 기본정보 label을 상단 정렬, input/select 높이를 48px로 통일했다.
2. 관리항목 버튼을 동일 행/동일 높이로 고정하고 선택 개수는 해제 버튼에 표시한다. 불필요한 0개 선택 줄과 별도 저장 카드는 없애고 상태/조회 링크를 버튼 아래 전체 폭에 배치했다. 카드의 중복 여백과 선택 문구도 줄였다. 저장 완료 후 오래된 ‘미저장 해제’ 안내는 지운다.
3. 관리항목의 MyPage에 저장 클릭 시 명시된 안내대로 건강정보 변경분을 먼저 저장한 뒤 해당 새 profile ID에 최종 관리항목을 연결해 저장한다. 앞으로 가서 별도 저장해야 하는 차단을 제거했다. 가상 예시, 유효하지 않은 입력, 다른 탭 최신본 충돌, 동의/소유권/CSRF/계정 표식 검증은 유지한다.
4. 두 API를 사용하는 순차 저장이며 단일 원자적 트랜잭션으로 표현하지 않는다. 중간 실패 시 건강정보 저장 완료와 관리항목 미확인을 구분해 알린다. 요청 UUID/본문/단계 스냅샷을 유지하고 응답 유실 재시도 시 이미 처리된 단계는 중복 생성하지 않는다. 불확실 상태에서는 입력/선택을 잠그고 같은 요청으로 재시도한다. 실제 완료는 서버 관리항목 재조회까지 확인한 뒤 표시한다.
5. 레이더는 유효한 나이·성별·수치·또래 평균이 있으면 산술 비율을 표시한다. 측정일·참고 기준 상태 등이 미입력이어도 숫자 비교는 가능하며 임상 판정은 기존 상세 평가에서 계속 보류한다. 누락 값은 0으로 채우지 않는다. 범위를 벗어난 입력은 기존 입력 범위 검증을 적용한다. 또래 평균이 정상/치료 목표라는 해석은 하지 않는다.
6. 가로 그래프는 기존 일반 참고선/수치 라벨과 내 수치 위치/수치 라벨을 함께 표시한다. 조건 미확인 시 참고선은 ‘일반 참고 기준’으로 보여주며 개인 건강 판정을 하지 않는다. HDL 성별 미선택은 기존 남성40/여성50 설명에 대응하는 두 참고선을 표시한다. 새 임상 수치/자동 처방을 추가하지 않는다.

## 적용
서버 종료 → ZIP 내용을 프로젝트 루트에 경로대로 덮어쓰기 → bash run_local.sh → Ctrl+F5.

- 관리항목을 고르고 MyPage에 저장하면 건강정보 변경분도 함께 반영한다. 저장 완료 메시지를 확인한 뒤 MyPage 나의 관리항목을 연다.
- 저장 결과 확인·재시도가 나오면 같은 버튼으로 재시도한다. 부분 완료 메시지는 전체 성공과 구분한다.
- DB 초기화/마이그레이션/npm 빌드 없음. 기존 MyPage 셸/건강정보·이력·식품/계획은 유지한다.

## 검증
- 변경 JS 문법 및 기존 frontend21+JS41=62개 통과.
- 실제 Spring/Security/Thymeleaf+별도 H2 Chromium에서 사진과 같은 미입력 조건(참고 상태 미확인·측정/검사일 없음)과 8개 지표 가상 입력으로 재현했다. 레이더8개 산술 비교/상세 임상 badge 보류/가로 참고선·내 수치 표시를 확인했다. 검증 데이터는 건강 판정으로 사용하지 않았다.
- 건강정보 미저장 변경+관리항목3개를 summary에서 함께 저장 → profile ID 연결/MyPage 조회 → 건강정보 재수정+항목1개 해제 → 서버가 care 저장 후 성공 응답을 잃은 모의503 → 부분 완료 메시지/입력 잠금/동일 UUID·본문 재시도 → 변경된 체중/관리항목2개와 MyPage 실제 카드/새 로그인 양쪽 복원을 확인했다. JS 오류 없음.
- 1440/1180/800/556/390/320px에서 나이/성별 높이48px, 두 열일 때 y/너비 일치, 버튼 y/높이 일치, 페이지 가로 넘침 없음 확인. 정렬은 같은 프레임의 DOM 좌표로 측정했다. 테스트 summary 이미지도 내부 확인했다.
- 사용자 MySQL에는 접근하지 않았다. 서버 Java를 변경하지 않았으므로 이전 서버 테스트38개를 이번에 재실행한 것으로 표현하지 않는다. 운영 임상 검증 완료와 구분한다.
