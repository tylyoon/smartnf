# 건강별 식품 가이드: 선택 카드별 후보·보류 안내

2026-11-05 / 150절까지 적용한 환경 기준

## 변경
- 혈압/혈당/혈중 지질/체중 관리를 선택하면 그 카드의 식품 선택 기준과 일반 후보만 표시한다. 다른 지원 질환을 합쳐 후보 교집합을 만들던 표시 방식을 선택 카드 기준으로 바꿨다.
- 신장질환/기타 만성질환 카드를 추가하고 해당 카드를 선택했을 때 개인별 추천 보류 이유와 영양정보 직접 조회 경로를 표시한다. 이때 이전 카드의 음식 목록·영양 상세·일반 기준은 지운다.
- 초기 표시를 혈압 관리 카드로 명확히 한다. 내 관리항목 확인은 건강정보 확인 링크이며 전체 질환으로 목록을 일괄 보류하는 표시와 구분한다.
- 신장질환·기타 만성질환이 등록되어도 그 사실만으로 혈압 등 지원 카드의 후보를 일괄 차단하지 않는다. 저장된 진단을 바꾸지 않고 해당 두 질환을 별도 주의사항으로 표시한다.
- 단, 나이·참고 기준 적용 범위·알레르기·복약·개인 식사 제한 등의 기존 차단 검사는 유지한다. 기존 엔진이 신장질환에서 먼저 반환하더라도 두 미지원 질환만 분리한 복사본에서 남은 검사를 수행해 뒤의 제한이 누락되지 않게 했다. 원본 건강정보/알레르기는 변경하지 않는다.
- 후보는 선택 카드의 일반 정보이며 복합 질환을 가진 개인의 적합성·치료식 판정으로 표현하지 않는다. 함께 등록된 신장질환·기타 만성질환 주의사항은 목록 위에서도 보인다.
- 카드 변경 시 이름 검색·하위 분류·페이지를 초기화한다. 이전 카드의 검색어 때문에 새 카드가 빈 목록처럼 보이지 않게 했다.
- 영양 기준/근거 원문/알레르기 제외/DB·MyPage 저장/개인 진단 데이터에는 변경이 없다.

## 적용
서버 종료 → ZIP을 프로젝트 루트에 폴더 구조대로 덮어쓰기 → bash run_local.sh → Ctrl+F5.

확인 순서: 혈압 관리(관련 후보/등록 질환 주의사항) → 신장질환(해당 안내/후보 숨김) → 기타 만성질환(해당 안내) → 혈압 관리(후보 복원).

별도 DB 초기화/마이그레이션/npm 빌드 불필요.

## 검증
- Node 관련25개 통과. 선택 카드 한정 조건, 원본 유지, 미지원 질환 카드별 보류, 혈압 후보 허용+동반질환 주의, 알레르기/복약/개인 제한/형식 검증 보존 회귀 포함.
- 실제 템플릿/JS/영양 원자료를 사용한 Chromium에서 복합 질환 등록+혈압 후보 표시, 관련 주의사항 표시, 카드별 근거 한정, 신장질환/기타 선택 시 목록/상세/기준 초기화, 다시 혈압 후보 복원, 혈당 카드 독립, 복약 제한 재검증, 1440/1180/800/390/320px 넘침/JS 오류 없음 확인.
- 브라우저 검증의 개인 API는 비로그인 대역 응답을 사용했고 계정 쓰기는 실행하지 않았다. 실제 Spring/MySQL/개인 계정 전체 검증과 구분한다.
