# 기본정보 성별·레이더 안내·관리항목 카드 해제와 저장 간소화

2026-11-04 / 147절 적용 환경 기준

## 변경
- 나의 상태의 기본정보에서 나이 다음에 성별 선택란을 배치했다. 기존 sex 필드/선택값/계정 저장·복원은 유지하며 임의 기본값이나 필수 선택은 추가하지 않는다.
- 레이더에 성별 미선택·20세 미만/나이 미입력 안내와 기본정보 바로가기 버튼을 추가했다. 버튼은 나의 상태를 열고 성별 또는 나이에 초점을 둔다.
- 표의 열을 내 수치/또래 평균/평균 대비(%)로 명확히 했다. 수치 미입력과 성별/나이 부족 사유를 구분한다. 또래 평균이 정상 기준·개인 치료 목표가 아님을 설명하고 정상 참고 기준은 기존 지표별 상세 평가로 안내한다. 평균 데이터·임상 기준·비교 조건·비율 계산식은 바꾸지 않았다. 성별을 선택해도 측정일 등 다른 조건이 부족하면 기존 사유에 따라 비교를 생략한다.
- 나의 관리항목의 별도 저장 카드/제목/계정 전체 해제 버튼/중복 확인 체크를 제거했다. 기존 summary 안에 선택 항목 해제/MyPage에 저장/처리 결과/조회 링크만 둔다.
- 관리항목 카드를 클릭하거나 선택 체크를 누르면 색상과 테두리가 바뀐다. 상세 열기·참고 링크 클릭과 해제 대상 선택은 구분된다. 선택 항목 해제는 화면 목록만 변경하며, MyPage에 저장을 눌러 최종 계정 목록에 반영한다.
- 저장 클릭은 화면의 최종 목록을 명시 확정한 뒤 기존 서버 API로 저장하고 재조회하여 확인한다. 모두 해제한 빈 목록은 확인 후 저장할 수 있다. 이 경우 건강정보·이전 관리항목 이력은 삭제하지 않는다. 가상 예시·건강정보 미저장/충돌·동의·소유권·CSRF 검증과 동일 요청 재시도를 유지한다.

## 적용
1. 서버를 종료한다.
2. ZIP의 src/docs를 프로젝트 루트에 폴더 구조대로 덮어쓴다.
3. bash run_local.sh 실행 후 Ctrl+F5.
4. 나의 상태 → 기본정보에서 성별 확인/건강정보 저장.
5. 관리항목 선택·확정 → 카드 선택/선택 항목 해제 → MyPage에 저장 → MyPage 조회.

DB 초기화/마이그레이션/npm 빌드 불필요. 계정의 기존 건강정보와 저장 이력/음식 선택·계획은 유지한다.

## 검증
- 변경 JS 문법과 frontend21+기존 JS41=62개 테스트 통과.
- 실제 Spring/Security/Thymeleaf와 별도 H2 계정의 Chromium에서 성별 기본정보 위치/단일 필드/저장·복원, 성별/수치 부족 안내, 기본정보 초점 이동, 성별·필요 측정 조건 충족 후 레이더 표시, 또래 평균/정상 기준 문구 확인.
- 관리항목3개 저장 → 카드 선택 강조 → 1개 해제(계정은3개 유지) → 저장2개 → 나머지 카드 선택/전체 해제 → 확인 후 저장0개 → MyPage 빈 상태 확인. 카드 빈 공간 선택/상세 열기 구분, 별도 저장 카드 제거, 1440/1180/800/390/320px 페이지 넘침 없음, JS 오류 없음 확인.
- 서버 코드 변경이 없어 전체 Java 테스트를 이번에 재실행한 것으로 표현하지 않는다. 사용자 MySQL에 접근하지 않았으며 사용자 환경 확인은 적용 후 필요하다.
