# 추천 재료 활용 음식 확대 — 2026-10-26

## 확인 위치
ZIP을 기존 smartnf 프로젝트에 병합하고 서버 재시작 → Ctrl+F5 → http://localhost:8080/preview/health/recommendations

**음식** 탭에서 **생선요리 / 두부요리 / 채소요리 / 반찬** 분류를 선택하세요. 기존 밥류와 식재료 탭도 유지합니다.

## 추가 범위
| 분류 | 레시피 후보 수 | 보유 원본의 예 |
|---|---:|---|
| 생선요리 | 14 | 가지연어구이, 고등어구이, 맛간장삼치구이 |
| 두부요리 | 38 | 고구마두부스테이크, 두부말이찜, 두부구이·버섯소스 |
| 채소요리 | 45 | 시금치들깨무침, 오이파프리카새콤무침, 브로콜리 관련 요리 |
| 기타 반찬 | 8 | 간장소스를 곁들인 새우전복찜, 라이스페이퍼 새우롤 |
| 새 후보 합계 | 105 | 제목·원문 재료를 함께 대조 |

기존 음식 5개와 합쳐 **음식 110개**, 기존 식재료 105개와 합쳐 **전체 215개**입니다. 레시피 ID별로 서로 다른 원본은 별개 항목으로 유지합니다. 분류는 연결 재료에 따른 SmartNF 표시 분류이며 공식 식품군·문화권 분류가 아닙니다.

조건별 교집합과 알레르기 검사 후 실제 표시 수는 달라집니다. 고혈압 하나만 있는 경우 음식110개가 후보이며, 기존 가상 조건인 **당뇨병+고혈압+이상지질혈증+감량**에서는 기존 밥2개와 새 레시피9개인 **음식11개**가 표시됩니다. 단, 다른 입력된 제한이 없다는 소프트웨어 시험 조건입니다.

## 이번에 적용한 원칙
사용자 요청에 따라 **추천 대상인 재료를 활용할 수 있는 음식 후보**로 범위를 확대했습니다. 레시피 전체의 질환 적합성·영양 적합성을 판정한 결과가 아닙니다.

1. 기존 근거 연결 식재료의 이름을 레시피 제목과 원문 재료 목록 양쪽에서 확인합니다.
2. 해당 재료에 연결된 관리조건/출처/원본 식품 ID를 레시피의 연결 근거로 보존합니다. 원본 식품 ID는 추천 재료의 근거 참조이며 레시피 배합 재료 코드 확정이 아닙니다.
3. ‘반찬’ 레시피 중 재료/조리 단계가 있는 항목을 사용합니다. 후식·밥·국물류, 튀기기 또는 조리 단계의 튀김 표현, 김치·장아찌·짱아지·절임·피클·훈제 이름은 이번 범위에서 제외합니다. 표현 기반 필터로 모든 영양 위험을 검출한 것은 아닙니다.
4. 오이고추를 오이로 보는 등 확인된 부분일치 혼동은 제외합니다. 두부/연두부/순두부처럼 제목의 재료 계열명이 연결되어도 같은 원재료 코드·같은 영양값이라고 확정하지 않습니다.
5. 복수 관리조건은 연결 재료의 근거가 모든 조건을 함께 충족하는 후보만 표시합니다. 신장질환/명시된 개인 제한 등 기존 보류는 그대로 유지합니다.

제목이나 재료에 추천 재료가 있어도 다른 재료/부위/양념/조리법/양이 달라질 수 있습니다. 예를 들어 시금치 요리에 돼지고기·유제품이 함께 들어갈 수 있습니다. 해당 식품 전체가 저지방/저염/혈당 관리에 적합하다고 자동 판정하지 않습니다.

## 카드에 보이는 내용
- **추천 재료 활용 · 생선요리/두부요리/채소요리/반찬** 배지
- **연결 재료**: 기존 추천 대상과 연결된 재료 이름
- **음식 후보** 및 전체 적합성 미판정 안내
- **추천 이유·출처 확인**: 재료를 추천 대상에 연결한 근거
- **재료와 조리법 보기**: 식품안전나라에서 이미 수집한 해당 레시피의 실제 원문 재료/조리법
- **양념·소스·기름·다른 재료와 분량 확인** 안내
- **나의 선택에 담기**: 아래 선택한 음식 그룹에 추가. 재클릭하면 선택과 해당 카드 제거.

## 영양값과 알레르기
- 새 레시피의 기준량/배합 코드가 검증되지 않았으므로 **영양값과 영양 적합 점수를 표시하지 않습니다**. 기존 음식 DB의 100g 영양값을 이름이 비슷한 레시피로 복사하지 않습니다.
- 기존 음식5개는 원본 음식 DB100g 영양표를 그대로 유지합니다.
- 알레르기 미입력은 ‘알레르기 제외 미적용’을 표시하고 진행합니다.
- 알레르기 항목을 입력하면 단일 원재료 검증이 안 된 음식/레시피는 기존 규칙으로 제외합니다. 재료 문자열만 보고 첨가물/교차접촉까지 안전하다고 판정하지 않습니다.

## 선택·확정 계약
새 ID는 `mfds_recipes:원본레시피ID`입니다. 일반 음식 DB의 `mfds_dishes:...`와 분리하여 같은 이름을 병합하지 않습니다.

공유 food-flow/food-registration/food-identity에 새 원본 ID를 읽고 음식으로 표시하는 지원만 추가했습니다. 기존 선택/확정의 추가 저장·삭제·재클릭·새로고침 정책은 유지합니다. 다른 페이지의 화면 구성은 변경하지 않았으며 해당 페이지 작업 시 필요한 개선은 아래 후속 항목으로 남깁니다.

## 후속 작업 기록
- **MyPage**: 원본 종류/레시피ID/선택 당시 근거 재료와 조건/규칙 버전/실제 섭취량을 기록하고 삭제·수정·조건 변경 시 재검토.
- **AI레시피식단**: 실제 배합 중량·인분·가열상태·재료코드 검토 후 전체 영양을 계산하고, 다른 재료·양념·복합질환을 함께 검증. 이번 후보를 개인 최적 식단이나 예상 건강 효과로 자동 전환하지 않음.
- **Backend**: 일반 음식코드와 레시피 원본ID를 구분하여 저장할 모델 및 조건/근거 버전 이력 설계. 이번 DB 변경 없음.
- **Python**: 명칭/별칭·가공상태 검토, 누락된 조리 재료/인분·기준량 확보, 실제 제품 알레르기 표시/소스 배합 정보 수집 후 후보 정확도를 보완.
