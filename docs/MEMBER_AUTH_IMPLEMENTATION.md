# 회원가입·DB 로그인 1차 구현 안내

작성일: 2026-10-28. 상태: 구현본 작성 / Java 빌드·Spring 서버·실제 MySQL 적용 확인 대기.

## 이번 변경

- SmartNF 한 프로젝트 안에 일반 회원가입, 이메일 로그인, 로그아웃과 USER/ADMIN 권한 경계를 연결했다.
- V1__create_member_auth.sql에 ERD의 회원·일반 인증·SNS 계정·권한·동의 문서·동의 이력 6개 테이블을 정의했다. SNS 테이블은 구조만 준비했으며 실제 SNS 인증은 미연결이다.
- 이메일은 공백 제거·Locale.ROOT 소문자화, 표시 이름은 필수·중복 허용이다. 이 정책은 이번 개발 검증용 기본값이며 운영 전 확정이 필요하다.
- PasswordEncoder의 식별자 포함 해시로 비밀번호를 저장한다. 입력은 12~64자 및 UTF-8 72바이트 이내로 제한해 기본 bcrypt의 입력 한계에서 조용히 잘리지 않도록 한다.
- 가입 시 회원·인증 정보·USER 권한·동의 이력을 한 트랜잭션에 저장한다. 이메일 중복 UNIQUE 충돌은 전체 롤백한다. 가입 요청의 role/memberId 값으로 권한·소유자를 결정하지 않는다.
- Spring Security의 기존 CSRF·세션 고정 방어·관리자 경로·읽기 전용 체험 정책을 유지한다. 기존 개발용 user/실행마다 생성된 암호 로그인은 회원 DB 인증으로 대체된다.
- 가입은 /signup, 로그인은 /login. 기존 /preview/account/signup은 시연 화면을 보존하고 실제 가입으로 이동하는 링크만 추가했다.
- JPA 설정은 유지하고 회원 Repository는 JdbcTemplate의 명시적 SQL로 구현했다. JPA Entity 자동 테이블 생성은 사용하지 않는다. SQL/트랜잭션 경계가 분명한 초기 인증 구현이며, 전체 프로젝트의 JPA 사용을 제거한 것이 아니다.

## 개발 검증용 동의 문서

운영용 약관·개인정보 처리방침이 확정되지 않아 기존 내용을 운영 약관으로 간주하지 않았다. /signup/documents/terms 및 /signup/documents/privacy에 dev-20261028 버전의 로컬 개발 안내를 표시하고, 그 버전에 대한 동의만 기록한다. 기존 /policies/** 페이지는 변경하지 않는다.

화면에는 실제 개인정보 대신 가상 표시 이름·시험용 이메일·다른 서비스에서 쓰지 않는 암호를 입력하도록 표시한다. 실제 건강정보 저장 동의·운영용 정책·보관/삭제 절차는 이번에 완료하지 않았다. 공개 운영 전 문서와 처리 정책을 확정하고 새 버전을 추가해야 한다.

## 계정 변경과 브라우저 임시 상태

공통 헤더가 서버에서 확인한 내부 회원 식별 키를 제공하고 account-state.js가 기존 SmartNF 임시 키를 정리한다. 익명→회원, 회원 A→B, 회원→익명 경계에서는 건강정보·관리항목·알레르기·선택/확정 식품·월간/섭취 임시 기록·과거 레시피 참조를 지운다. 무관한 저장소 키는 지우지 않는다. 따라서 로그인 시 기존 익명 선택을 자동 등록하거나 이어받지 않는다.

같은 회원의 일반 페이지 이동·새로고침은 이 스크립트가 기존 확정 상태를 지우지 않는다. 기존 미확정 새로고침 초기화 정책은 그대로다. 뒤로가기 캐시에 남은 양식·건강 결과는 pagehide에서 숨기고 캐시 복귀 시 서버 페이지를 다시 읽는다. 저장소 접근 실패 시 본문에 안내하고 오래된 정보의 사용을 막는다.

이 처리는 회원 DB 저장이 아니다. 다른 탭이 이미 보여주는 화면을 실시간 삭제하는 기능, 세션 강제 만료·탈퇴·관리자 정지 시 기존 세션 일괄 종료는 후속이다.

## 적용 전 확인

1. 실행 중인 서버를 Ctrl+C로 중지한다.
2. 기존 프로젝트를 백업하고 ZIP을 smartnf 루트에서 병합한다. ZIP 최상위는 docs/, src/, build.gradle이다. 비밀키·.env·실행 스크립트는 포함하지 않는다.
3. 현재 DB의 Flyway 이력을 먼저 확인한다.

```sql
USE smartnf;
SELECT installed_rank, version, description, success
FROM flyway_schema_history
ORDER BY installed_rank;
SHOW TABLES;
```

실제 이력 행은 이번에 확인하지 못했다. V1이 이미 적용된 이력이 있거나 기존 회원 테이블이 있으면 서버를 시작하지 말고 결과를 공유한다. schema_history가 있다는 이유로 비어 있다고 가정하거나 V1·기존 체크섬을 덮어쓰지 않는다. Flyway repair/clean, 기존 DB 삭제는 하지 않는다.

4. Java 21과 Gradle 환경에서 아래 테스트를 실행한다. 각 SpringBootTest의 최우선 테스트 속성으로 H2 URL·계정·드라이버를 고정하고 Flyway를 비활성화한다. 환경변수에 운영 DB 주소가 있어도 테스트 속성이 우선하도록 구성했다. src/test/resources에 전용 스키마를 둔다. 실제 MySQL에는 테스트 데이터를 쓰지 않도록 구성했다.

```bash
bash ./gradlew test --no-daemon
node src/test/js/account-state.test.cjs
```

H2는 테스트용 의존성이므로 최초 실행 시 다운로드가 필요하다. H2 테스트 스키마는 테스트 DB용 호환본이며 MySQL Flyway SQL 실행 검증을 대신하지 않는다.

5. 테스트 결과 확인 후 기존 방법으로 서버를 실행한다. Flyway가 시작 시 6개 테이블과 개발용 동의 문서 2개를 생성한다. DB 변경을 원하지 않으면 이 단계 전 멈춘다.

```bash
bash run_local.sh
```

Flyway DDL 실패 시 MySQL의 일부 DDL이 남을 수 있다. 반복 시작·수동 이력 변경 대신 오류와 SHOW TABLES 결과를 확인한다. 계정·암호·키가 포함된 로그는 공유하지 않는다.

## 사용자 확인 순서

1. http://localhost:8080/signup 에서 새 가입 화면과 문서 링크 확인.
2. 시험용 이메일(예: member-test@example.test), 가상 이름, 시험용 비밀번호로 가입 → 로그인 화면의 가입 완료 안내 확인.
3. 가입한 이메일로 로그인, 공통 헤더의 로그인 상태와 로그아웃 버튼 확인. 기존 user 임시 암호는 사용하지 않는다.
4. 같은 이메일의 대소문자 변경 가입은 중복 차단, 다른 암호·비밀번호 불일치·동의 누락은 가입 실패 확인.
5. 일반 회원으로 실제 /admin/** 접근이 차단되는지 확인. 실제 관리자 업무 화면은 이번 작업에 추가하지 않았다.
6. 헬스케어에서 임시 선택 후 로그아웃·다른 시험용 계정 로그인·브라우저 뒤로가기 시 이전 회원의 상태가 이어지지 않는지 확인.
7. 동일 회원 안에서 헬스케어 관리항목 선택·해제·확정·식품가이드 이동·재방문 동작 재확인.

비밀번호 해시 자체를 공유하지 않고 저장 형태를 확인하려면 다음과 같이 조회한다.

```sql
SELECT m.id, m.display_name, m.status, r.role,
       CASE WHEN c.password_hash LIKE '{bcrypt}%' THEN 'bcrypt' ELSE '확인 필요' END AS password_storage
FROM members m
JOIN local_credentials c ON c.member_id=m.id
JOIN member_roles r ON r.member_id=m.id;
SELECT member_id, document_id, decision, recorded_at FROM member_consents;
```

## 검증 결과

| 검사 | 결과 |
|---|---|
| account-state.js 문법 | Node 검사 통과 |
| 계정 경계 6조합·무관한 키 보존 | Node VM 검사 통과 |
| 저장소 실패·BFCache 복귀 | Node VM 검사 통과. 실제 브라우저 검증은 별도 |
| 변경분·민감 설정 제외·템플릿 구조 | 정적 검토 |
| Java 빌드·JUnit/H2 통합 검사 | 미실행. Gradle 다운로드 도중 services.gradle.org DNS 조회 실패, Java는 17만 제공됨 |
| 실제 브라우저·모바일 렌더링 | 미실행. Playwright 브라우저 실행 파일 없음 |
| 실제 MySQL DDL·Spring 통합 | 사용자 환경 확인 대기 |

JUnit에는 해시 저장·정규화 로그인·중복 가입 롤백·USER 전용 생성·CSRF·필수 동의·문서 버전·비밀번호 불일치·UTF-8 길이·정지 회원 로그인 차단 검사를 추가했다. 기존 보안 검사는 DB 회원을 생성해 검사하도록 변경했고 화면 테스트의 데이터소스 제외 설정은 H2 전용 설정으로 대체했다. 테스트 코드를 작성한 것과 통과한 것을 구분한다.

## 남은 작업

- SNS 제공자 선택·앱 설정·실제 인증·기존 회원 재인증 후 연결/해제.
- 이메일 소유 확인·계정 찾기·비밀번호 재설정의 구현 범위 확정.
- 최초 관리자 지정·권한 변경 이력·정지/탈퇴에 따른 기존 세션 만료.
- 운영용 약관·개인정보·민감정보 동의, 탈퇴/철회·삭제/보관·재가입 정책.
- 건강정보·측정값·관리항목·식품·MyPage 기록의 상세 물리 ERD 및 회원 저장 API.
- 가입/로그인 남용 방지와 운영 모니터링은 공개 운영 전 별도 설계.
- 헬스케어 전체 연동·자료 근거 검증과 추출본 설치 검증.

이번 ZIP은 1차 회원 기능의 로컬 검증용 구현본이다. SNS 로그인·회원 건강정보 저장·MyPage·운영 배포 완료본으로 표시하지 않는다.
