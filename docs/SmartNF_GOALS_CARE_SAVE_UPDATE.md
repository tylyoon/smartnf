# 관리 목표 복수 선택·나의 관리항목 계정 저장 개선

2026-11-04 / 146절 적용 환경 기준

## 변경
- 건강정보의 관리 목표를 건강한 식습관/다이어트/만성질환 관련 관리 복수 체크로 변경했다. MyPage 수정도 같은 복수 체크를 제공한다. 다이어트의 저장값은 기존 ‘체중 관리’를 유지해 옛 값과 호환한다.
- 프로필 검증에서 목표 배열의 허용값·중복을 검증한다. 기존 goal VARCHAR(40)의 V0/V1/V2 단일 코드와 호환되는 다중 코드로 저장/조회하므로 마이그레이션이나 DB 초기화가 없다. 기존 단일 목표·과거 기록도 조회한다. 목표 외 건강정보 항목은 유지한다.
- 관리항목 계정 저장/전체 해제/확인 체크를 선택 완료 후 표시되는 ‘나의 관리항목’ 안으로 이동했다. 기존 멀리 떨어진 패널은 제거했다. 저장 안내·상태·MyPage 나의 관리항목 링크를 같은 영역에 표시한다.
- 스크린샷의 관리항목은 가상 예시로 확정된 상태다. 기존 계정 저장은 이를 차단했지만 안내와 버튼 위치가 떨어져 사용자가 실패 이유를 알기 어려웠다. 로그인 계정 화면은 내 입력 기준으로 시작하고, 사용자가 명시적으로 가상 예시를 선택한 경우 본인 자료로 저장하지 않으며 이유를 같은 패널에 표시한다.
- 이름 없는 계정 저장 확인 체크로 건강정보의 예시 여부/관리항목 확정 상태가 무효화되지 않게 했다. 실제 건강정보 입력 수정은 계속 재확정 대상이다.
- 건강정보 최신 ID와 미저장 변경 검증을 유지한다. 관리항목 저장 성공 후 서버 /care를 재조회해 해당 저장본이 최신인지 확인하고 MyPage 저장 완료를 표시한다. 저장 중 피드백/오류 위치를 제공한다. 관리항목은 MyPage 나의 관리항목에서 조회한다.
- 기존 계정 소유권·CSRF·동의·계정 표식·UUID·최신본 충돌 검사 유지. 새 질환/알레르기 필드·외부 AI 전달·자동 처방·기존 계정 자료 삭제 없음.

## 적용
1. 서버 종료 후 ZIP을 프로젝트 루트에 폴더 구조 그대로 덮어쓴다.
2. bash run_local.sh 실행 후 Ctrl+F5.
3. 건강정보에서 관리 목표를 복수 체크하고 건강정보 확정 · MyPage에 저장.
4. 내 입력 결과 기준에서 관리항목 선택 → 선택한 관리항목 확정.
5. 표시된 나의 관리항목 아래에서 확인 체크 → 확정 관리항목을 계정에 저장.
6. ‘MyPage 관리항목 저장 완료’ 확인 후 MyPage 나의 관리항목 링크로 조회.

가상 예시로 선택했다면 비교·평가의 내 입력 결과로 전환하여 다시 선택/확정한다. 건강정보를 수정했다면 먼저 건강정보를 저장하고 관리항목을 다시 확정한다. 기존 DB 초기화/새 migration/npm 빌드 불필요(빌드 번들 포함).

- React 번들 빌드 및 frontend21+기존 JS41=62개 통과.
- 실제 Spring Boot/Security/Thymeleaf/H2 Chromium: 목표3개 저장·복원, MyPage 복수 목표 체크/2개로 수정, summary 내부 관리항목 저장/서버 재조회/MyPage 표시, 새 건강정보 후 관리항목 재확정, 새 로그인에서 두 자료 복원, 명시적 가상 예시 저장 차단·JS 오류 없음 확인.
