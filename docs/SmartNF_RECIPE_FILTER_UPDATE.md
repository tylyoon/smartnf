# 음식 계열 위치·참고 레시피 유무 필터

2026-11-03 / `SmartNF_DISH_RECIPE_FLOW_UPDATE.zip` 적용 프로젝트 기준.

1. 서버를 종료한다.
2. ZIP의 `src/`, `docs/`를 프로젝트 루트에 그대로 덮어쓴다.
3. `bash run_local.sh`로 실행하고 브라우저에서 Ctrl+F5를 누른다.
4. 식재료·식품 영양정보 → 음식·조리·가공을 선택한다.

DB 마이그레이션·npm 설치·데이터 재생성은 필요 없다.

- **음식 계열:** ‘어떤 식품을 찾으세요?’ 옆. 모바일에서는 제목 아래.
- **참고 레시피:** 기존 계열 위치에 전체/있는 음식/없는 음식. 다른 검색 조건과 함께 적용.
- 확인 예: 계열 전체·기타 조건 없이 ‘있는 음식’195건 / ‘없는 음식’20,799건. 영양자료 행 수이며 음식 종류 수가 아니다.
- ‘있는 음식’ → 밥·죽·스프 → 식품 이름 입력란의 죽 → 세부 분류 1 호박죽5건 → 결과 상세 → 담기 → 참고 레시피 보기 → 원문 체크·연결 후 ‘참고 레시피 선택됨’을 확인한다. 연결을 해제해도 후보가 있으므로 ‘있는 음식’에 남는다.
- ‘등록된 참고 레시피 없음’은 현재 보유 자료에서 이름 일치 후보를 찾지 못했다는 뜻이다. 사용자 미선택 상태와 다르다.
- 자료 읽는 중/실패는 ‘없음’으로 분류하지 않는다. 실패 시 일반 영양 검색은 유지되며 레시피 확인을 다시 시도할 수 있다.
- 참고 레시피 묶음은 여전히 이 화면의 임시 선택이며 계정 저장·영양 계산에 포함되지 않는다.

Node/보안 JS20개 및 Chromium 1440/390px 검증 완료. 실제 Spring/MySQL 구동은 적용 후 확인한다. 변경 내용과 보안·검증 범위는 `SmartNF_IMPROVEMENTS.md` 127절에 기록했다.
