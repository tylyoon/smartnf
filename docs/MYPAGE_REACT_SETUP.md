# React 개인 MyPage 1차 적용 안내

이번 파일은 **개인 화면 구성 기반**입니다. 외부 LLM 생성은 아직 연결되지 않았으며 제안 버튼은 로컬 키워드 규칙입니다.

## 1. 적용

1. 기존 프로젝트를 백업하고 실행 중인 서버를 Ctrl+C로 종료합니다.
2. ZIP 안의 `src/`, `frontend/`, `docs/`를 프로젝트 루트에 같은 경로로 덮어씁니다. 외부 `smartnf/` 폴더는 없습니다. `.env.local`이나 비밀번호 설정은 변경하지 않습니다.
3. 프로젝트 루트에서 테스트합니다.

```bash
bash ./gradlew test --no-daemon
```

4. 성공하면 기존 명령으로 서버를 실행합니다. 기존 run_local.sh의 Flyway 마이그레이션 계정을 그대로 사용합니다.

```bash
bash run_local.sh
```

5. MySQL에서 확인합니다. 수동 CREATE나 이전 Flyway 파일 수정/repair는 필요하지 않습니다.

```sql
USE smartnf;
SELECT version, description, success FROM flyway_schema_history ORDER BY installed_rank;
SHOW TABLES LIKE 'member_mypage_layouts';
```

V6 `create personal mypage layout`, success=1을 확인합니다. V1~V5는 기존 상태를 유지합니다. 오류가 나면 오류 부분만 공유하고 비밀번호/환경 파일 전체를 보내지 마세요.

## 2. 화면 확인

1. 로그인 후 http://localhost:8080/mypage 에 접속합니다. 기존 화면이 남으면 Ctrl+F5를 누릅니다.
2. **내 화면 구성하기** → `혈압과 체중만 보여줘` → **로컬 구성 제안받기**. 카드 두 개가 미리보기에 나타나는지 확인합니다.
3. 체크박스로 카드를 추가·숨기고 카드의 위로/아래로 버튼으로 순서를 바꿉니다. **확인한 구성 저장**을 눌러야 계정에 반영됩니다.
4. 새로고침 및 로그아웃·재로그인 후 같은 구성이 복원되는지 확인합니다.
5. 다른 계정에 로그인하면 앞 계정의 구성이 보이지 않아야 합니다. 새 계정은 기본 구성부터 시작합니다.
6. 같은 계정의 두 탭에서 서로 다른 구성 저장 시 오래된 탭은 충돌 안내가 나오는지 확인합니다. 다시 불러오기 후 재편집합니다.
7. 건강정보 저장에 동의하지 않은 계정에는 수치 대신 동의 안내가 표시됩니다. 카드 구성만 저장할 수 있습니다.
8. 기존 개발용 가상 건강정보를 저장한 계정은 혈압/체중/관리항목이 본인 저장본과 일치하는지 확인합니다. 기록 없음/미입력과 숫자 0을 혼동하지 않아야 합니다.
9. 다른 탭에서 건강정보 저장 동의를 철회한 뒤 기존 화면의 건강정보가 제거되는지 확인합니다. 철회 후 카드 코드·순서는 남아도 삭제한 건강정보는 복원되면 안 됩니다.
10. 모바일 너비에서 가로 넘침·카드 이동 버튼·키보드 포커스를 확인합니다.

카드를 숨기는 것은 실천 행동 중단·건강기록 삭제가 아닙니다. 구성 요청에 이름·진단·건강 수치 등을 입력하지 마세요.

## 3. 프런트 소스 수정 시에만

번들 파일을 포함했으므로 일반 적용에는 Node 설치/빌드가 필요 없습니다. JSX를 수정하면 아래를 실행합니다.

```bash
cd frontend
npm ci
npm run build:mypage
```

React/React DOM/esbuild 기존 잠금 버전을 사용합니다. 전체 `npm run build`는 기존 채팅과 MyPage를 함께 빌드합니다.

## 4. 현재 한계

- 외부 LLM, 자유로운 자연어 전체 해석, 임의 사용자 코드 생성은 미구현입니다.
- 식사/활동/실천 기록 입력, 변화 분석, 생성형 리포트, 정보 이용 감사 이력은 후속 작업입니다.
- 건강정보 상세/저장 이력/동의 페이지는 기존 공통 상세 화면을 유지합니다. 새 React 구성은 `/mypage`에 적용됩니다.
- 이번 전달 환경에서 React 빌드·모의 API 기반 DOM 검사·순수 Java 계약/구문·기존 Node 검사를 수행했습니다. Gradle은 다운로드 DNS 오류로 전체 실행하지 못했으며 실제 MySQL V6·브라우저 화면은 사용자 확인이 필요합니다.
- 실제 민감정보를 받는 공개 운영 전 암호화/키/보관·삭제/HTTPS/감사 등 개선 문서 105절의 보안 계획을 적용해야 합니다.
