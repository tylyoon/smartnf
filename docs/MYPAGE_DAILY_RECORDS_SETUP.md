# 오늘 기록하기 — 적용과 확인

직전 계정 설정·가상 기간 그래프 수정본까지 적용한 프로젝트가 기준입니다. 개발용 가상 입력으로 확인하세요.

## 1. 적용

1. 프로젝트·개발 DB를 백업하고 서버를 Ctrl+C로 종료합니다.
2. ZIP 안의 `src/`, `frontend/`, `docs/`를 프로젝트 루트에 같은 경로로 덮어씁니다.
3. 테스트합니다.

```bash
bash ./gradlew test --no-daemon
```

4. 성공 후 서버를 실행합니다.

```bash
bash run_local.sh
```

5. MySQL에서 V8 적용을 확인합니다. 수동 CREATE/repair/이전 Flyway 파일 수정은 하지 않습니다.

```sql
USE smartnf;
SELECT version,description,success FROM flyway_schema_history ORDER BY installed_rank;
SHOW TABLES LIKE 'health_daily%';
```

V8 `create daily health records`, success=1 및 새 테이블 3개가 보여야 합니다.

## 2. 새 동의 안내 확인

로그인 → http://localhost:8080/mypage/consent → 새 안내 `dev-health-20261102` 확인 → 동의 체크·저장 동의.

기존 회원도 새 안내에 재동의해야 합니다. 이전 본인 건강 저장본·관리항목은 지워지지 않고 재동의 후 다시 조회됩니다. 원하면 재동의 없이 철회 버튼으로 전체 건강기록을 삭제할 수 있습니다. 철회/탈퇴 검사는 버려도 되는 가상 계정으로만 진행하세요.

## 3. 실제 입력 위치

http://localhost:8080/mypage/daily 또는 MyPage의 **오늘 기록하기·기간별 조회**를 누릅니다. 변경이 안 보이면 Ctrl+F5를 누릅니다.

- 오늘 날짜를 불러온 상태에서 실천 여부·메모·체중·혈압을 입력하고 **일일 기록 저장**을 누릅니다. 전부 비우면 저장되지 않습니다.
- 관리항목이 없으면 건강정보 화면에서 행동 선택·계정 확정을 먼저 합니다. 측정값·하루 메모만 저장할 수도 있습니다.
- 혈압은 수축기/이완기를 함께, 환경과 시간대를 확인해 입력합니다. 체중은 소수 1자리까지 가능합니다. 입력 범위는 정상 판정 기준이 아닙니다.
- 날짜 선택 후 **날짜 기록 불러오기**를 눌러 과거 기록을 수정합니다. 날짜 입력만 바꾸어 다른 날에 자동 저장하지 않습니다.
- 하루 대표값 1개를 관리합니다. 여러 번 측정/평균·식사량/활동량 상세 입력은 아직 제공하지 않습니다.
- **수정 내용 저장** 후 새로고침·재로그인하여 같은 내용이 나오는지 확인합니다.
- **이 날짜 기록 내용 삭제**는 내용 삭제이며 충돌 방지용 날짜/삭제 버전은 남습니다. 새로 작성할 때 최신 기록을 불러와야 합니다. 건강 동의 철회/회원 탈퇴 시 이 메타데이터도 삭제합니다.

## 4. 기간 조회

기간 적용·빠른 조회 버튼을 사용합니다(최대 366일). 날짜별 표와 그래프가 연결됩니다. 혈압 환경/시간대·체중 시간대별로 그래프가 나뉘며 미기록 사이를 연결하지 않습니다. 그래프 점/실천 날짜를 누르면 상세 내용을 확인하고 해당 날짜 편집으로 이동할 수 있습니다.

기존 대시보드의 혈압/체중 카드는 건강정보 저장본 기준입니다. 일일 기록은 이 화면에서 별도로 관리하며 초기 건강 프로필·목표를 자동 덮어쓰지 않습니다.

## 5. 계정/오류 확인

- 다른 계정에서는 앞 계정의 일일 기록이 보이지 않아야 합니다.
- 두 탭에서 같은 날짜를 수정하면 오래된 탭은 충돌 안내가 나와야 합니다. 최신 기록 다시 불러오기 후 재편집하세요.
- 저장 응답이 늦으면 입력을 그대로 두고 같은 저장 버튼으로 재시도할 수 있습니다. 이미 저장된 최신 내용을 변경/삭제한 후 오래된 요청으로 덮어쓸 수는 없습니다.
- 건강정보 동의 철회·탈퇴 시 일일 기록/실천/요청 참조도 삭제되어야 합니다. 재동의해도 복원되지 않아야 합니다.
- 가상 예시는 계정으로 자동 복사되지 않습니다. 실제 음식/활동 상세 기록·건강 평가·자동 피드백은 후속 작업입니다.
- 화면/입력 동작 검사는 전달 환경에서 모의 API로 수행했습니다. 실제 Spring/MySQL·브라우저 결과는 사용자 확인이 필요합니다. 오류가 나면 해당 오류 부분만 공유하고 환경 파일·건강 원문·비밀번호는 보내지 마세요.
