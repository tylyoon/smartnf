# SmartNF 277 · 주문 결제 방식에 맞는 PG 버튼 표시

2026-11-19

## 수정 이유

기존 모의 결제 완료·입고 검수 완료 주문에도 PG 테스트 결제 버튼이 표시되어, 클릭하면 서버에서 '승인 완료된 발주를 선택하세요'라는 안내가 나왔습니다. 274의 PG 버튼 노출 조건이 주문 상태만 검사하고 PG 결제 기록 유무를 구분하지 않은 화면 오류입니다. 서버는 이미 결제된 모의 주문을 PG로 새로 결제하지 않도록 차단하고 있었습니다.

## 변경 동작

| 주문 상태와 방식 | 표시 |
|---|---|
| 판매자 승인 전 | 판매자 승인 후 결제 가능 안내 |
| 승인 완료·미결제, 열린 변경 요청 없음 | 구매·정산·관리 담당자에게 PG 테스트 결제 |
| PG 준비·승인·배송·입고 처리 중 | 해당 담당자에게 PG 결제·환불 관리 |
| 모의 결제 완료·배송·입고·정산 | 결제 방식 · 모의 결제 표시, 새 PG 결제 버튼 없음 |
| PG 준비 해제·실패 후 승인 완료 | PG 테스트 결제 재시도 가능 |
| PG 준비 해제·실패 후 모의 결제 | 모의 결제로 구분하며 기존 모의 취소 동작 유지 |

## 적용

ZIP을 프로젝트 루트에 폴더 구조 그대로 덮어씁니다. 실행 중인 서버를 평소처럼 다시 시작하고 구매자·공급자 창에서 Ctrl+Shift+R을 한 번 누릅니다. 기존 DB·키 설정·거래 내역을 변경하지 않습니다.

기존 후추 입고 검수 완료 주문과 양송이 모의 결제 완료 주문은 PG 결제로 전환하지 않습니다. PG 검증에는 아직 결제하지 않은 판매자 승인 완료 주문이 필요합니다. 해당 주문이 없다면 PG용 1포장 발주 한 건을 만들고 판매자가 승인한 뒤 구매자가 PG 테스트 결제를 선택합니다.

## 검증

화면 DOM 자동 검증 14건, 변경 JS 구문 검사 통과. 모의 결제·부분 입고·입고 완료의 PG 버튼 제거, 승인 완료 주문의 결제 시작, 실제 PG 기록이 있는 주문의 관리 진입, 정산 직무의 관리 카드 유지, 창고 직무의 결제 링크 제한, PG 준비 해제·실패 후 재시도 및 모의 결제 전환, 열린 변경 요청의 신규 결제 제한을 확인했습니다. 사용자 PC의 화면 반영과 토스 외부 테스트 결제 통신은 후속 확인 대상입니다.
